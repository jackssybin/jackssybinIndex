想做个小工具、搭个能跑的 Demo，第一步永远是找数据：哪个 API 能白嫖、要不要注册 Key、浏览器能不能直接调？很多人卡在这一步就放弃了。

GitHub 上有个专门解决这事的仓库叫 public-apis，一个免费公共 API 的收藏清单，Star 数已经冲到 **50 万**，是全站最热门的项目之一。但收藏不等于会用，这次我把它整个克隆到本机、写脚本把那份 379KB 的 README 逐条解析，还跑通了它自带的测试。这篇就用一手数据讲清楚：它怎么组织、哪些接口真能零成本调，以及最关键的——**拿这两千多个 API，到底能聚合出什么应用**。

## 一份 README 凭什么撑起 50 万 Star

很多人以为这种清单就是随手堆链接，其实它的工程化程度不输正经软件。

![仓库真实构成与质量门禁](/root/jackssybinIndex/content-ops/public-apis-aggregator/media/structure.png)

我本地实测：当前收录 **2465 个标准 API、51 个分类**，今年还新增了一个 **MCP 服务器专栏，收录 60 个 MCP**；累计约 2406 位贡献者、7019 次提交，MIT 协议，2016 年建仓到现在仍然每天更新，没有烂尾。

它最反直觉的地方是：**整个"数据库"就是一份 README.md**，没有 SQLite、没有 JSON 数据文件，所有接口都用 Markdown 表格维护，每行严格遵循六列——API、描述、Auth、HTTPS、CORS、链接。Auth 只接受 No/apiKey/OAuth 几种固定枚举，CORS 只接受 Yes/No/Unknown 三个值。

这种"拿 Markdown 当结构化数据"的做法能十年不失控，靠的是强制门禁：format.py 校验字段和枚举、links.py 在 PR 阶段自动查死链、scripts/tests 下 **31 个单元测试我本地跑了一遍全部 OK**、外加 3 个 GitHub Actions 自动巡检。贡献规则还明确拒收营销 PR，收录的接口必须能免费公开调用。

我在解析时还注意到一个细节：它的分类不是一成不变的。早期只有开发、天气、金融这些传统类目，这两年陆续长出了 Cryptocurrency（114 个）、Machine Learning（61 个）这种新赛道，今年更是直接加了 MCP Servers 专栏，把给 AI Agent 调用的工具服务器单独归了一类。一个纯靠社区维护的清单，能跟着技术范式迁移而不是僵化，这其实比单纯的接口数量更能说明它的生命力。

## 能不能白嫖、能不能纯前端调，看这两张表

对做聚合应用的人，接口总数其实最没用，真正决定架构的是两个字段：**要不要认证、浏览器能不能跨域直连**。我把 2465 个接口全统计了一遍。

![认证与CORS分布，656个接口可纯前端直连](/root/jackssybinIndex/content-ops/public-apis-aggregator/media/auth-cors.png)

认证上，1200 个接口完全免认证（约 49%），1104 个要申请 apiKey（45%），150 个走 OAuth（6%）。也就是说接近一半的接口连注册都不用，发请求就给数据。

跨域上，1080 个明确支持 CORS（44%），1055 个标 Unknown（43%），330 个明确不支持（13%）。注意标 Unknown 不是不能用，是清单没验证、要你自己发请求确认；标 No 的浏览器一定调不动，必须走后端代理。

两个条件取交集，得到一个对独立开发者极友好的数字：**656 个接口同时满足"免认证 + 支持 CORS"**。这意味着不用服务器、不用 Key、不怕密钥泄露，一个静态网页里写个 `fetch()` 就能直连出数据，做原型的成本几乎为零。我还从池子里抽了几个真实接口验证思路：天气类的 Open-Meteo、NASA POWER，测试数据类的 DummyJSON、FakerAPI，娱乐类的 Cat Facts，金融类甚至有实时富豪榜 Billionaire Tracker，全部注册零成本、返回标准 JSON。

## 重点：2465 个 API 能聚合出什么？8 个方向

这是我最想讲的部分。下面每个方向都基于真实分类的条目数，标了依赖、要不要 Key、难度和变现路径，不是拍脑袋。

![8个可落地的聚合应用方向矩阵](/root/jackssybinIndex/content-ops/public-apis-aggregator/media/ideas.png)

**① 个人数据仪表盘（难度★，订阅制）**：聚合天气、加密货币、金融分类，一屏看天气、持仓、汇率。免 Key 接口就能起步，最适合新手的第一个项目。

**② 垂直行业情报台（难度★★，B 端 SaaS）**：用政务（142 个）、新闻、开放数据（98 个）做政策、招标、监管监控。这类多要 apiKey，但 B 端愿意为"省掉人工盯盘"付高价。

**③ 开发者 API 集市（难度★★，流量/佣金）**：基于最大的开发类（251 个）加测试数据，做可检索、可在线试调、可收藏的 API 导航站，本质是这个清单的产品化升级版，靠 SEO 和置顶佣金变现。

**④ 旅行规划聚合器（难度★★，CPS 分销）**：交通（103）+ 地理编码（120）+ 天气（46）+ 汇率（35）组合，输入目的地就给路线、天气、汇率、景点，接酒店机票分佣。

**⑤ 健身运动数据站（难度★，广告+会员）**：运动（76）+ 健康（54），做赛事比分、NBA 数据、球队排名，免 Key 接口密集、更新频繁。

**⑥ 娱乐内容盲盒（难度★，涨粉引流）**：游戏（120）+ 动漫 + 音乐，做随机梗图、猫狗图、冷知识这类"一键来一条"，门槛最低，用来快速涨粉给主产品引流。

**⑦ 加密金融看板（难度★★，交易导流）**：加密（114）+ 金融（118）+ 汇率，做实时币价、汇率、富豪榜，行情接口多免 Key，常见玩法是给交易所导流。

**⑧ MCP/Agent 工具网关（难度★★★，基础设施）**：最前沿的方向，用新增的 60 个 MCP 服务器加开发类 API，做面向 AI Agent 的统一鉴权、用量统计、请求路由，卡的是 Agent 时代的基础设施位。

要提醒一句：不同方向会复用同一批接口，所以数字相加会超过 2465，这很正常。而且无论选哪个，**都得先做好"健康巡检 + 统一缓存 + 鉴权代理"三层底座**，否则免费接口的限流和失效会很快拖垮体验。

这八个方向怎么选，我给个判断逻辑：如果你是想练手或快速验证想法，优先选①⑤⑥这类免 Key 密集、一两个周末能出活的；如果你冲着赚钱去，②的 B 端情报和⑧的 Agent 网关客单价和壁垒最高，但需要后端和鉴权能力；④旅行和⑦金融则胜在变现路径成熟，CPS 分佣和交易导流都有现成模式。最忌讳的是一上来就想做"大而全的 API 导航"，和原清单正面竞争没有意义，垂直切一个细分人群反而更容易跑出来。

## 清醒一点：它是黄页，不是免运维中台

50 万 Star 容易让人产生"躺着做产品"的错觉，但边界很清楚。

![能力边界与生产建议](/root/jackssybinIndex/content-ops/public-apis-aggregator/media/verdict.png)

它是人工策展的免费 API 黄页，字段规范、可筛选、跟进了 MCP、MIT 协议随便复用元数据；但它**不保证接口长期可用**（当前有 2811 个未关闭 issue，不少就是失效反馈），不提供托管、SLA、统一鉴权或缓存，免费额度和限流全是各服务商自己定，43% 的接口 CORS 状态未知、必须实测。

所以上生产环境至少做三件事：后端加代理层、密钥永不进前端；定时健康检查加自动降级备用源；核心业务别只押一个免费接口，同时守好各 API 的服务条款。

如果你想动手，建议直接从那 656 个"免 Key + CORS"接口里挑一个，先在浏览器 Network 面板手动发一次 fetch 确认能返回 JSON、没有跨域报错，再写代码、加超时和缓存，从能跑的 Demo 平滑演进到能用的产品，而不是一上来就背上整套后端架构。
