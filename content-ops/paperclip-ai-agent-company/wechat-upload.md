先描述一个很多人正在经历的混乱现场。

你电脑上开着 20 个 Claude Code 终端：这个在改登录，那个在写测试，第三个不知道为啥跑飞了，token 哗哗地烧。重启一次电脑，所有上下文归零。你根本记不清哪个窗口在干什么。

这半年大家解决这个问题的思路，是教你怎么「写」一群能互相调用的 Agent。

但有个 8 个月冲到 **10.8 万 Star** 的项目，思路完全反过来。它叫 **Paperclip**，README 里有句话我看完就懂了：

**「如果 OpenClaw 是一名员工，Paperclip 就是公司本身。」**

它不做 Agent，不给你模型，也不教你写 Agent。它干的事是：把你已经在用的 Claude Code、Codex、OpenClaw、Cursor、Gemini、Grok、Hermes 这些 Agent，编排成一家**有组织架构、有预算、有审批、有 KPI 的公司**。

我把仓库整个拉下来（1.2 万多个文件，已经合并 2700 多个 PR）通读了一遍，还实际装了一遍。这篇讲清楚它到底怎么运作，以及谁现在就该用。

## 用法像任务管理器，底层是一家公司

Paperclip 的使用流程只有三步：

**第一步，定目标。** 比如「做一个冲到 100 万月收入的 AI 笔记应用」。

**第二步，招人。** CEO、CTO、工程师、设计师、市场——想用哪个 bot、哪个模型都行。

**第三步，审批、开跑、看仪表盘。** 你定好预算，剩下的交给团队。

界面长得像 Trello、Linear 那种任务看板，但底层全是公司管理的东西：组织架构、预算、治理、目标对齐、Agent 协调。

它最核心的概念叫**目标血缘**：任务挂在项目下面，项目挂在公司目标下面。所以 Agent 拿到任务时，看到的不是一句干巴巴的标题，而是「我为什么要做这件事」的完整背景。

以前你得手动从各个地方拼凑信息、反复提醒 bot 你到底想干嘛——这个动作它直接给你自动化了。

## 四根柱子，撑起一家 AI 公司

它认为一群 AI Agent 要真的产出，只有四件事必须做好，整个产品就围着四根柱子造：

![Paperclip 的四大支柱](/root/jackssybinIndex/content-ops/paperclip-ai-agent-company/media/pillars.png)

**任务管理**：活都是工单，对话按任务归档，重启不丢。Agent 干活、人在审批关卡上验收——看 diff、看截图、看测试结果。

**组织架构**：人和 Agent 混编在一张组织图里。每个 Agent 有头衔、有上级、有岗位职责。密钥按权限发，公司之间有围墙。特别妙的一点：Agent 操作 GitHub 时，身份可以归属为指挥它干活的那个真人——出了问题找得到责任人。

**员工培训**：内置技能工作室（Skill Studio），可以给 Agent 写技能、做评测、跑测试，甚至做「绩效评审」。技能有版本号，搞砸了能回滚。

**智能体操作系统**：跨模型运行时、沙箱、MCP 服务器、SSO、权限管控、成本控制——让上面这些真正能跑的基础设施。

## 不是套壳：底下是一整套控制平面

最打动我的是，它把多 Agent 协调里那些最难的脏活累活，全做对了。

![Paperclip 控制平面的 12 个核心子系统](/root/jackssybinIndex/content-ops/paperclip-ai-agent-company/media/architecture-v2.png)

挑几个最见功力的说：

**原子任务认领**——一个任务只有一个负责人，加上执行锁，绝不可能出现两个 Agent 同时抢一个活。这是分布式任务系统的经典坑。

**心跳机制**——Agent 平时是「睡着」的，被派活、收到消息、或者到了定时计划才醒来。底层是落数据库的唤醒队列，带预算检查、密钥注入、失败自愈。

**预算硬停止**——花费按公司、Agent、项目、模型等七个维度记账，可以设阈值告警和硬性暂停。这个直击最吓人的场景：循环跑飞了，等你发现已经烧掉几百美元、额度打爆。

**例行任务**——客服、社媒、报表这种周期性工作，用定时计划或 webhook 触发，每次执行都自动生成工单、有负责人、有历史。再也不用人记得去启动。

还有多公司隔离、插件系统、加密凭据、完整的活动审计日志。

## 谁能被录用？只要会收「心跳」

它不挑 Agent，官方原话是：**「只要能接收心跳，就录用。」**

Claude Code、Codex、Cursor、Gemini、OpenCode、Grok、Kimi、Pi、OpenClaw、Hermes……都在适配名单里。还支持自定义进程、HTTP 接口和外部适配器。

每个 Agent 可以单独选模型，但任务、技能、权限、历史全汇总在一处。GitHub、Notion、Railway 甚至你自己的 MCP 服务器都能接进来，Slack、Discord、Telegram 也能对话。

## 五分钟跑起来，真·自托管

这点我很喜欢：它是 MIT 协议，真正开源可商用，而且**不强制注册账号**。

Node 装好之后，一行命令：

```bash
npx paperclipai@latest onboard --yes
```

想先零风险试试，有个预置好 CEO Agent 的试驾模式：

```bash
ANTHROPIC_API_KEY=... npx paperclipai test-drive
```

从源码跑也简单，装完依赖 `pnpm dev`，UI 和 API 起在本地 3100 端口，**PostgreSQL 数据库是嵌入式自动创建的，零配置**。生产环境再换成你自己的 Postgres 和 Docker。

## 冷静一下：它不是万能的

为了不写成软文，有几点必须说清楚。

**它和我之前写过的 OpenBot 不是一类东西。**

![三种用法对比](/root/jackssybinIndex/content-ops/paperclip-ai-agent-company/media/compare.png)

OpenBot 是桌面工作台，给每个 Agent 配独立工位和浏览器，偏个人协作；Paperclip 是服务端控制平面，面向 7×24 自治、多用户、讲预算和合规的团队。打个比方：前者给工程师发电脑，后者直接帮你开公司。

**成熟度要客观。** 8 个月 10.8 万 Star 确实疯狂，但它同时挂着 **6766 个未关闭 issue**，Agent 聊天、记忆知识库、云部署等功能还标着「实验性」，桌面 App 甚至还没交付。星标涨得快不等于生产环境稳，重要业务上之前务必充分测试。

**遥测默认开启。** 它声明只采匿名数据、不碰任务内容和密钥，介意的话一个环境变量 `PAPERCLIP_TELEMETRY_DISABLED=1` 就能关。

**安全红线没变。** Agent 拿到的依然是能跑命令、改代码、连外网的真实权限。它给了你审批关卡、预算硬停、沙箱这些缰绳，但自治 Agent 的风险本身不会消失——生产环境请用认证模式、最小权限密钥，并且保留人在审批环节。

## 谁现在就该上车？

- **已经并行养了一堆 Agent 又管不过来的开发者和小团队**：工单、预算、持久会话解决的是真痛点，`test-drive` 零成本试；
- **想让 AI 7×24 自治干活、又要审计和控成本的人**：心跳、例行任务、预算硬停都是现成的；
- **有合规和多用户需求的企业试点**：MIT 可商用 + SSO/RBAC，相比那些非商业授权的同类产品，这是巨大优势；
- **求稳的保守团队**：建议再观望，先在非核心流程跑跑看。

我越来越确信一件事：当一个人就能指挥几十个 AI 员工，真正的瓶颈早就不是「怎么让模型更聪明」，而是**怎么给这群员工建组织、定预算、立规矩、做考核**。

Paperclip 做的，就是把整套公司管理制度软件化。Agent 时代的 ERP 长什么样，它给了目前我见过最完整的答案——尽管这家「公司」自己也还在热火朝天地施工。
