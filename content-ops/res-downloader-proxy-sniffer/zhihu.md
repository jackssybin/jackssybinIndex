# 视频号的视频为什么能被「下载器」抓到？从一个 20.4k Star 开源项目谈起

视频号、小程序、小红书的视频没有保存入口，这不是技术做不到，而是平台刻意不做。市面上的「视频号下载器」往往被传得很玄，好像破解了什么加密协议。最近我把 GitHub 上 20.4k Star 的开源项目 res-downloader（Apache-2.0，Go + Wails）拉下来通读了核心源码，结论很朴素：**它没有破解任何东西，本质上是一个替普通用户做好资源筛选的 MITM 代理，和 Fiddler、Charles 同原理。** 这篇文章基于源码梳理它的机制与边界，也顺带讲清楚这类工具为什么能成立、在什么情况下必然失效。

## 一、问题的关键：媒体 URL 用户看不见

IDM、Motrix 这类下载器的工作前提，是用户提供一个真实媒体地址。而封闭平台的视频地址有两个特点：一是在 HTTPS 加密通道里传输，二是 URL 附带动态鉴权参数，有时效性。用户在 App 界面层面拿不到这个地址，下载器自然无从下手。

res-downloader 的切入点正是在这里：既然地址会在网络请求中出现，那就让流量先经过自己。

## 二、机制：本地代理、自签证书、实时筛选

通读源码后，它的数据流可以概括为四步：

第一，启动时程序在本机 127.0.0.1:8899 端口启动基于 goproxy 的代理服务（端口默认值在 core/config.go），并修改系统代理指向它。

第二，安装阶段要求用户信任的证书，是程序生成的自签 CA 根证书。core/proxy.go 的 setCa() 将证书设置为 goproxy 的中间人 CA。这是 MITM 解密 HTTPS 的标准做法，与 Charles 首次启动安装证书完全相同。

第三，媒体请求经过代理时，响应处理函数检查状态码（200/206/304）与 Content-Type，将响应类型映射为视频、音频、图片类别，命中规则才采集。

第四，命中的资源通过 WebSocket 推送到前端列表。用户看到的不是数千条混杂请求，而是一个干净的资源清单。

需要强调的是，目标平台的正常播放不受影响——代理只是在转发过程中「看见」了资源，并没有攻击服务器。

## 三、两个超出「玩具」水平的工程设计

**规则引擎。** core/rule.go 实现了文本规则集，支持全匹配、`*.domain` 通配子域、`!` 否定规则，带读写锁。嗅探范围由规则文本决定而非硬编码，这是机制与策略分离的典型写法。

**插件结构。** 代理维护一个域名到插件的注册表。默认插件按响应类型通吃；而针对腾讯系的插件（core/plugins/plugin.qq.com.go）包含若干有针对性的逻辑，经源码核对包括：识别 finder.video.qq.com 的视频号视频流并校验 Origin 来自 mp.weixin.qq.com；对小程序相关响应进行 JS 改写并注入 fetch 配合资源上报；对加密的视频号内容，由 core/aes.go 实现 AES 解密，对应界面里的「视频解密（视频号）」操作。

![插件注册表与 QQ 系特判](/root/jackssybinIndex/static/images/res-downloader-proxy-sniffer/qq-plugin.png)

扩展新平台只需实现域名声明与请求、响应两个钩子并注册，主流程不动。这种设计解释了它为什么能长期维护、持续增加平台支持。

## 四、使用条件与必然失效的场景

实际使用有两个硬前提：设备信任自签 CA，手机抓包时手机与电脑处于同一局域网并将 Wi-Fi 代理指向电脑的 8899 端口。Win7 用户受 WebView2 限制只能使用 2.3.0 版本。

![操作清单与避坑](/root/jackssybinIndex/static/images/res-downloader-proxy-sniffer/checklist.png)

有两类场景是原理性失效，而非软件 bug：其一，App 实施证书绑定（SSL Pinning）时，客户端只信任自身预置证书，任何用户安装的 CA 都无法中间人解密；其二，异常退出后系统代理未还原会导致断网，手动关闭系统代理即可恢复。直播录制与超大文件下载也不在它的能力范围内，作者本人建议分别使用 OBS 与 Motrix。

## 五、如何评价这类工具

从技术视角看，res-downloader 的价值不在于「下载」，而在于产品化：它把一项需要专业知识的抓包流程，压缩成一次点击加一份清单，规则引擎和插件结构是其可维护性的根基。

从风险视角看，需要记住两点：MITM 代理在运行期间具备解密本机全部 HTTPS 流量的能力，因此来源可信、用完即退、确认代理还原，比工具本身的功能更重要；下载内容的版权属于原平台与创作者，个人学习存档与二次传播是性质不同的两件事。

对普通用户，它是低门槛的存档工具；对开发者，它也是一份 goproxy 与 Wails 结合的可读实战样本。项目地址：https://github.com/putyy/res-downloader
