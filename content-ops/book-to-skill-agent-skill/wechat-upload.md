# 一本技术书读完就忘？这个开源工具让 Agent 替你记住，提问 token 直降 51 倍

你花一周啃完一本 500 页的技术书。三个月后要用第 7 章那个框架，脑子里只剩"书里好像讲过"。

把 PDF 拖给 AI？它要么凭印象胡说，要么说"我没有这本书"。分章复制粘贴？它每轮都重新翻目录、重新读，token 账单悄悄涨。

最近 GitHub 上一个叫 **book-to-skill** 的开源项目（MIT 协议）换了个思路：**别把书喂给 AI，先把书"编译"成一个 AI 技能（Skill），让 Agent 用到哪章读哪章。** 官方用真实书籍实测，回答同一个问题，比把整本书塞进上下文**少烧 24–51 倍 token**。

我把源码克隆下来、在本机实跑了一遍。下面不是 README 翻译，是我自己验证后的判断。

![book-to-skill 概念图](/root/jackssybinIndex/content-ops/book-to-skill-agent-skill/media/01-showcase.png)

## 一、贵的不是读书，是"翻书"

官方给这个浪费起了个很准的名字：**发现循环税（Discovery Loop Tax）**。

一个读 PDF 的 Agent 不只是读，它还要导航——先拉目录、猜章节、打开不对再退回重来。这部分开销跟你的问题大小无关，纯粹是"翻书"产生的税，而且每一轮对话都要重交一遍。

三种老办法，各有死穴：直接搜 PDF 只能得到一串页码；整本塞进上下文，每轮重复烧钱还容易在长文里走神；自己做笔记，最后得到一份再也不会打开的 200 行文档。

book-to-skill 的办法是：**把"结构化"的成本在转换时一次性付清**，之后每次提问，token 只跟答案本身挂钩。

## 二、51 倍是怎么测出来的

我最看重它没吹牛——所有数字用 tiktoken 实测，仓库里还附了能自己复现的脚本。

回答一个精准问题时进入上下文的 token：

- 《Think Python 2》：整本 119,264，book-to-skill 约 5,000，**省 24 倍**
- 《Working Backwards》：整本 175,253，**省 35 倍**
- 《AI Engineering》：整本 256,287，**省 51 倍**

为什么能恒定在 5,000？因为生成的技能里有一个约 4K token 的常驻核心（讲清全书心智模型+章节索引），加上你问到的那一章（约 1K token）。问到哪章读哪个文件，其余章节一分钱不占。

而整本转换一遍的成本，按 Claude Sonnet 4.5 价格估算，**平均约 1 美元一本书，只付一次。**

## 三、我在本机实跑了一次

光看数据不过瘾，我用仓库自带的测试样例跑了提取命令：

```
python3 scripts/extract.py evals/fixtures/pd00-synthetic-book.txt
```

真实输出：识别出 3 章（numeric）、141 个词、检测到目录，并在临时目录生成 full_text.txt 和 metadata.json。

![提取器实跑输出](/root/jackssybinIndex/content-ops/book-to-skill-agent-skill/media/02-extractor-output.png)

这里有个源码级细节：那份样例的章节标题是**葡萄牙语** `Capítulo 1`，工具照样准确切出 3 章。说明章节识别不是写死英文 "Chapter"，而是按多语言的"第 N 章"数字模式匹配——中文"第 1 章"同样成立。

## 四、它由两半组成

读完约 2,900 行 Python 源码，架构很清晰：

![两段式架构与提取器分流](/root/jackssybinIndex/content-ops/book-to-skill-agent-skill/media/03-architecture.png)

**前一半是确定性的 Python 提取器**，只管把文档变干净文本。PDF 文字书用 pdftotext（即时），技术书用 docling（约 1.5 秒/页，但保住表格和代码块）；EPUB、DOCX、HTML、RTF、MOBI 也都支持。

**后一半是 AI 生成器**，严格按一份 761 行的说明书，把文本提炼成技能文件。注意它的原则是"**提取结构，不是写摘要**"——产出的是命名框架、决策原则、方法步骤、反模式，而不是读后感。

最终是一套分层文件：SKILL.md（核心）、chapters/（每章一文件按需加载）、glossary、patterns、cheatsheet。同一份文件能被 Claude Code、GitHub Copilot CLI、Amp、Hermes Agent 直接读取。

这里要专门说一下"为什么是分层文件"。它背后是大模型一个很现实的脾气：上下文被压缩（compaction）时，通常只保留最前面的约 5,000 token。所以生成器刻意把最重要的心智模型全部前置进 SKILL.md，而把细节章节沉到磁盘上。你不问，这些章节就不进上下文；你一问，索引会精确地把 Agent 指到对应文件。这等于把一本书做成了"懒加载"——首页常驻，详情点开才加载，跟网页性能优化是同一个思路。

而那份 cheatsheet 也不是术语表的重复。作者在 v1.0 版专门改了一版规范：旧版的速查表是 9 行名词解释、0 条决策规则；新版反过来，0 行名词、32 条"遇到 X 就用 Y"的决策规则，还要求每个有深度的章节必须复现一个书中的完整范例。从"这是什么"升级成"该怎么做"，这才是 Agent 干活时真正需要的东西。

## 五、两个聪明的取舍，一个诚实的边界

**取舍一：按书型选提取器。** 一本 103 页技术 PDF，pdftotext 只要 0.1 秒但表格代码全丢（0 表格 0 代码块）；docling 跑 164 秒，却保下 48 个表格、36 个代码块。工具会先问你"文字书还是技术书"再分流——比无脑上重模型聪明。

**取舍二：切不了章就不硬切。** Pro Git、Moby-Dick 这类不用"第 N 章"标题的书，它无法自动分段，就老实提取、让你手动指定。扫描版 PDF（纯图片没文字层）更绝：它检查前几页后**立刻停下叫你先去 OCR**，而不是闷头处理完整本书、最后吐个空技能给你。

## 六、三步上手

```bash
# 安装（跨 Agent 通用一条命令）
npx skills add virgiliojr94/book-to-skill

# 检查本机各格式提取器是否就绪
python3 scripts/extract.py --check

# 指定文件/文件夹开始转换
/book-to-skill ./my-book.pdf
```

转完用 `/my-book 关键词` 提问，Agent 就读对应章节、照原文回答。内部架构文档、品牌手册、一叠论文笔记也都能喂——凡是你反复重新打开、希望自己背下来的资料，都是候选。

它还给了四种模式，不止"一键全转"：完整转换、仅分析（先看它提炼出哪些框架，满意了再生成）、从既有分析生成、以及对已有技能做**增量折叠合并**。最后这个很实用——你又读了几篇相关论文、或内部文档更新了，不用整本书重做，只要把新资料追加进去，它会把新内容合并进现有章节和索引。

多份资料也能一起处理：传入文件夹、glob 或一串文件路径，提取器会逐个解析，单个文件坏了只警告跳过、不影响其余，最后合并成带"来源标记"的全文，让 Agent 在回答时知道某段话出自哪份文件。

## 隐私和版权，帮你问清楚了

很多人第一反应是：我的书会不会被传走？答案是提取和分析这一步完全在你本机跑，工具本身不联网、不上传文件，仓库里也确实一本书的内容都不含——它只是个转换器。但要注意一个容易混淆的点：**生成那一步是你的 Agent 在调云端大模型**，喂给模型的文本遵循那家模型厂商自己的数据条款，这跟你平时发任何 prompt 是一样的，敏感内部文档用本地模型更稳妥。

版权上它也划得很清：生成的技能是框架名、定义、要点这类综合衍生笔记，不是原文照抄，规范里明确禁止复制原始段落，你可以当成自己的学习笔记。但**别把第三方付费书的技能公开分享**，那仍可能侵权，自己私有使用没问题；你自己写的东西、内部文档、开放许可材料则可以在许可证范围内自由分享。

## 谁该用，谁先等等

**该上**：常查厚书/内部文档、高频问 AI 的人（书越厚问得越多越划算）；用 Claude Code / Copilot / Hermes 的用户；在意隐私的人——提取全程本地，文件不外传。

**先等等**：想要零干预一键全自动的（扫描书得先自己 OCR、生成那步要调模型付约 1 美元）；想把第三方书的技能分享出去的（项目明确提醒可能侵权，第三方书请保持私有）；只有几页薄资料的，直接贴文本更省事。

我的建议：先拿一本你最熟的书跑"仅分析"模式，看它提炼的框架名有没有保留作者的精确表述——这是判断转换质量最直接的一刀。
