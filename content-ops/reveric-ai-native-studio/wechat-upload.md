AI 写作工具这两年出了很多，但用久了都有同一个毛病：它就是个聊天框。你得把人物小传、世界观设定一段段复制进去，项目一大上下文就断，AI 永远像个没读过你全稿的临时工，给完建议还得你自己手动粘回文档。

最近翻到一个开源项目，想从根上解决这个问题。它叫 **Reveric（幻界）**，是一个 Agent Native 的桌面创作工作台，从长篇小说、剧本改编一直做到短剧成片。

数据先放这儿：仓库 **10 月 22 日才建，半个月 724 Star**，但代码已经有 **2064 个 Dart 文件、约 75 万行**，最新 v0.8.1，Windows/macOS/Android 三端。我把仓库拉下来通读了一遍，讲讲它做成了什么。

## 核心思路：你的作品，就是 AI 的工作区

Reveric 最根本的设计，是让"作品"本身变成智能体能直接读写的工作区，而不是在外面挂个聊天框。

![本地优先加 Agent Native 的架构](/root/jackssybinIndex/content-ops/reveric-ai-native-studio/media/architecture.png)

四个关键词：**按需读取整部作品**——智能体自己去检索需要的章节和设定，你不用复制小传；**能操作所有模块**——它不是只给文本建议，而是真的能在编辑器、画布、导演台、剪辑台里动手改；**素材自动生成**——定妆照、分镜图、视频片段、音频直接生成到画布；**本地优先加自带 Key（BYOK）**——作品存本地 SQLite，模型你自己选、Key 你自己填，直连 OpenAI、Claude、Gemini、DeepSeek、Seedance 或任何自建网关，稿子不上传它的服务器。

对长篇创作者来说，"我的稿子在谁手里"是个真实的信任问题，本地优先是个明确立场。

## 五个工作台，把影视流水线装进一个 App

它不是单一编辑器，而是一条从文字到影像的完整生产线，每个环节独立、数据全程打通：

![五大工作台](/root/jackssybinIndex/content-ops/reveric-ai-native-studio/media/pipeline.png)

**小说**：树状大纲、自动保存、版本快照，加上人物、势力、伏笔、地图的多维设定库。最有意思的是实体关系图谱，专门记录角色关系的演变，还能让智能体写完一章后核验前后连续性，防"设定吃书"。

**剧本**：以小说为原著改编，左边读原著右边写剧本，编辑器按影视标准排版场次、动作、对话、转场。

**无限画布**：文字转视听的中枢，定妆照、分镜、生成的图音视频全是节点，镜头上下游关系一目了然，智能体可以自动拆分镜、写提示词、批量生素材。

**3D 导演台**：在三维场景里摆角色道具、设机位、规划推拉摇移、按时间轴预演，再导出构图参考图喂给视频模型——专治 AI 视频的"镜头语言失控"。

**剪辑台**：视频、叠加、对白、音效、音乐、字幕 6 轨时间线，分割、波纹删除、吸附都有，最后直接导出成片，不用再跳外部软件。

## 它不是套壳聊天，有完整的 Agent 工程

很多 AI 写作 App 本质就是包了个对话框。Reveric 在代码里有一整套 agent 架构，这是它和玩具的分水岭：主编排器加子智能体的委派模式、敏感操作要人工审批、专门的循环检测器防止 agent 陷入死循环、hook 机制做日志和结果验证、token 估算控制长作品的上下文预算。

还有个细节：它仓库根目录的 AGENTS.md 是给 AI 编程助手看的"工作契约"，写满硬约束——先读后写、冲突必须人工确认、业务数据默认软删除、任何硬删除都要明确授权。说明这个团队自己就用 agent 协作开发，并且把 agent 的行为边界制度化了。

## 插件 SDK 单独 MIT，想做生态

![插件系统](/root/jackssybinIndex/content-ops/reveric-ai-native-studio/media/plugin.png)

主程序是 AGPL，但插件 SDK 单独以 MIT 发布——这个许可选择很聪明，第三方开发者写插件不会被强传染。插件用 TypeScript 写，打包成独立运行时，宿主侧管权限、时限和导入校验，还支持从 GitHub 装技能并做 hash 校验。

另外它的设计文档态度也很鲜明：明确拒绝紫蓝渐变、玻璃拟态那种"AI 味 SaaS 风"，品牌人格是"平静、文学、从容的作家书房"，手稿永远是界面中心，AI 要安静、绝不能当主角。

## 三个必须说清的边界

**第一，AGPL-3.0 双许可。** 个人自用没问题，但基于它做 SaaS 给别人用就有网络传染性，得开源你的对应代码；闭源商用要买授权。注意只有插件 SDK 是 MIT，主程序不是。

**第二，它是编排层不是模型层。** 所有生成能力都来自你配的外部 API，README 也挂着 API 赞助商。断网它本身不产生任何智能内容，账单和选型责任都在你自己——BYOK 给自由，也给责任。

**第三，极早期。** 虽然代码量惊人，但才半个月、还在 0.8.x，schema 和 API 可能频繁变。适合尝鲜和学架构，严肃的长篇生产建议先小范围验证、勤备份。

## 怎么上手

到 Releases 下载安装包（Mac 的 dmg、Windows 的 exe、安卓 apk，也有 Linux 版）；设置里填好模型供应商的 Key 测通；新建作品或直接导入 TXT 原稿；然后在聊天里说"写第三章""把第一卷改编成剧本""给这场戏拆分镜并生成参考图"，剩下的交给智能体。

说到底，Reveric 对"AI 该站在创作的什么位置"给了个很清醒的答案：**作者是主角，手稿是中心，智能体是一个真能动手、但受审批和规则约束的搭档。** 这个 Agent Native 的产品范式，值得做 AI 创作工具的人认真看一遍。
