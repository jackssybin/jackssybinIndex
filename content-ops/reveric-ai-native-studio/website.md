AI 写作工具这两年不缺新玩家，但绝大多数停在"对话框+文档"：你把人物小传复制进聊天窗口，AI 给一段建议，你再手动粘回文档。项目一大、设定一多，上下文就断了，AI 永远像个没读过你全稿的临时工。

今天这个项目想解决的正是这个断点。它叫 [Reveric（幻界）](https://github.com/looplj/reveric)，定位是 **Agent Native 的桌面创作工作台**——从长篇小说、剧本改编一路做到短剧成片，而且智能体不是陪聊，是真的能在你的作品里动手。

先看一组反差很强的数据：仓库 **2026 年 10 月 22 日才建仓，到现在半个月，724 Star、178 Fork**；但代码量已经是 **2064 个 Dart 文件、约 75 万行**，最新版本 v0.8.1，支持 Windows/macOS/Android 三端。我把仓库克隆下来通读了产品文档、agent 架构和插件系统，这篇讲清楚它到底做成了什么。

## 一、核心主张：作品就是智能体的工作区

Reveric 最根本的设计选择，是把"作品"本身变成智能体可读写的工作区，而不是把 AI 当成一个外挂聊天框。四个关键词：

![Reveric 的本地优先 + Agent Native 架构](/images/reveric-ai-native-studio/architecture.png)

- **按需读取整部作品**：智能体自己检索需要的章节、人物设定和伏笔，不用你把上下文复制进对话框。底层是本地 SQLite（用 drift 做持久化），作品数据全在你自己的设备上；
- **智能体能操作所有模块**：小说、剧本、无限画布、3D 导演台、剪辑台，它都能直接上手改，而不只是输出文本建议；
- **素材自动生成**：角色定妆照、分镜参考图、视频片段、音频，由智能体调用模型直接生成到画布上；
- **本地优先 + BYOK（Bring Your Own Key）**：数据存本地，模型你自己选、Key 你自己填，直连 OpenAI、Anthropic、Gemini、DeepSeek、字节 Seedance、MiniMax H3，或任何 OpenAI 兼容的自建网关（Ollama、OneAPI、NewAPI 等）。

这个组合的意义在于：它不锁定模型供应商，也不把你的作品内容托管到它的服务器。对长篇创作者来说，"我的稿子在谁手里"是个真实的信任问题，Local-First 是一个明确的立场。

## 二、五大工作台：把影视工业流水线搬进一个 App

它不是单一编辑器，而是一条覆盖"文字→影像"的完整生产线，每个环节都是独立工作台、彼此数据打通：

![从小说到成片的五大工作台](/images/reveric-ai-native-studio/pipeline.png)

**1. 小说创作。** 树状大纲、自动保存、历史版本快照、一键专业排版，加上多维设定库——人物、势力、技能、伏笔、地点、地图、图鉴全部关联。最有意思的是**实体关系图谱**：记录角色关系的演变和重要节点，关系还有严谨的状态语义（当前关系、关系转变、关系恢复、已结束关系），写完一章可以让智能体提取事实、核验前后连续性，专门防"设定吃书"。

**2. 剧本改编。** 以小说为原著创建改编剧本，编辑器遵循影视行业标准，场次、动作、角色、括号、对话、转场、字幕这些元素标准化排版。支持左读原著、右写剧本的对照模式，智能体可以跨作品读取原著来提炼场景和台词。

**3. 无限画布。** 这是文字转视听的中枢。角色定妆照、场次节拍、分镜段落、生成的图片音频视频都以节点形式铺开，镜头的上下游引用关系和生图提示词一目了然。智能体能按剧本自动拆分镜、写提示词、批量生成素材。

**4. 3D 导演台。** 内置 3D 空间预演引擎（用了 flutter_scene 和自定义 shader）：在三维场景里摆角色、道具，设置特写/全景/正反打机位，规划推拉摇移运镜，按时间轴预演整场戏，再导出构图参考图喂给视频生成模型。这一步解决的是 AI 视频最头疼的"镜头语言失控"。

**5. 多轨剪辑台。** 6 轨专业时间线——视频主轨、画面叠加、角色对白、环境音效、背景音乐、多语言字幕，支持剪刃分割、波纹删除、多段吸附，最后直接导出成片，不需要再跳到外部剪辑软件。智能体可以自动把画布素材排上时间线、分割修剪、加字幕、分离音频、渲染预览。

## 三、Agent 架构：它不是套壳聊天，有完整的编排系统

很多"AI 写作 App"本质是包了个对话框。Reveric 在 `lib/shared/agent/` 下有一套完整的 agent 工程实现，这是它和玩具类产品的分水岭：

- **Orchestrator + Subagent**：聊天入口背后是一个不可见的主编排器（Chat Orchestrator），负责协调直接回复、工具调用，并把专门任务委派给子智能体（Chat Subagent）。子智能体可由用户管理或内置，是能力扩展层；
- **工具调度与审批**：`agent_tool_dispatcher.dart` 分发工具调用，`tool_approval.dart` 对敏感操作做人工审批——AI 不是想改就改；
- **循环检测**：`loop_detector.dart` 专门识别 agent 陷入重复调用死循环的情况并打断；
- **Hook 机制**：日志、追踪、待办续写（todo_continuation）、结果验证（verification）都以 hook 形式挂载；
- **token 估算与上下文管理**：`token_estimator.dart`、`agent_context_manager.dart` 控制长作品下的上下文预算，`round_assembler.dart` 组装多轮结果。

还有一个细节能看出工程成熟度：仓库根目录的 `AGENTS.md` 是给 AI 编程助手看的"工作契约"，里面写满了硬约束——先读后写、冲突必须人工确认、业务数据默认软删除（任何硬删除都要明确授权）、跨平台改动必须双端检查。这说明团队自己就在用 agent 协作开发，并且把 agent 的行为边界制度化了。

## 四、插件系统：SDK 独立 MIT，想做生态

Reveric 主仓库是 AGPL-3.0，但它的插件 SDK（`reveric-plugin-sdk`）单独以 **MIT** 发布，这个许可选择很聪明——降低第三方开发者的接入顾虑。

![插件系统与运行时隔离](/images/reveric-ai-native-studio/plugin.png)

插件用 TypeScript 写，通过 esbuild 打包成 IIFE，所有业务插件共用一个 JS 运行时但每个插件有独立 context；宿主侧（Dart）负责 API 分发、权限检查、调用时限和 ZIP 导入校验。内置插件（memory、web、deepseek）和第三方插件走完全相同的构建管线。它还有一套从 schema 自动生成 TS、Dart、Rust、JS 四处类型定义的机制，保证跨语言契约一致。另外 `skills-lock.json` 显示它支持从 GitHub 安装技能（类似 Agent Skill 的机制，带 hash 校验），创作能力可以继续外挂扩展。

## 五、设计纪律：明确拒绝"AI 味紫渐变"

在一堆霓虹渐变、玻璃拟态的 AI 产品里，Reveric 的设计文档（DESIGN.md / PRODUCT.md）态度非常鲜明。它的反面对照清单直接写着：不要通用 SaaS 仪表盘、不要霓虹 AI 聊天玩具风、不要紫蓝渐变、不要玻璃拟态、不要和稿子抢注意力的装饰。

品牌人格定义为"平静、文学、从容"，像一间作家的书房：羊皮纸色调、Georgia 字体、地图式细节，手稿永远是界面中心，AI 要"安静且可配置"，绝不能成为主角。可访问性上对齐 WCAG AA 对比度，支持键盘操作、reduced-motion、中英文双语一等公民。在 2026 年大家都在卷"更炫的 AI 视觉"时，这种克制反而是差异化。

## 六、必须说清的三个边界

**1. AGPL-3.0 双许可，商用要授权。** 个人学习、自用没问题，但 AGPL 有网络传染性：基于它做 SaaS 给别人用，就必须开源你的全部对应代码。想闭源商用需要联系作者买商业授权。注意只有插件 SDK 是 MIT，主程序不是。

**2. 它是编排层，不是模型层。** 所有生图、生视频、文本能力都来自你配置的外部 API，README 顶部也挂着 88API、秘塔 MiniMax H3 的赞助位。断网或 Key 失效时它本身不产生任何智能内容，生成成本和稳定性握在供应商手里——BYOK 给了你自由，也把账单和选型责任交给了你。

**3. 极早期项目，迭代极快。** 虽然代码量惊人，但建仓才半个月，版本还在 0.8.x，4 个 open issues，API 和数据 schema 可能频繁变动（仓库里有完整的 drift migration 体系在应对）。适合尝鲜和技术学习，严肃的长篇生产项目建议先小范围验证、勤备份，再决定是否 all-in。

## 适合谁，怎么上手

**适合**：想用 AI 但不愿放弃作者主导权的长篇小说/剧本作者、需要一站式短剧/漫剧生产管线的小团队、以及研究 Flutter 桌面端大型 agent 应用架构的开发者（75 万行 Dart 的工程组织本身就是很好的教材）。

上手四步：到 Releases 下载对应安装包（macOS dmg / Windows exe / Android apk，也有 Linux zip）；在设置里填模型供应商的 API Key 和 Base URL 并测通；新建小说或剧本作品（也能直接导入 TXT 原稿）；然后直接在聊天里说"写第三章""把第一卷改编成剧本""给这场戏拆分镜并生成参考图"，剩下的交给智能体。

## 结语

Reveric 最打动我的不是功能数量，而是它对"AI 在创作中该站什么位置"的回答：**作者是主角，手稿是中心，智能体是一个能真正动手、但受审批和规则约束的创作搭档。** 本地优先守住数据主权，BYOK 守住模型自由，五大工作台打通文字到影像，插件和技能系统留出生态空间。

它能不能从半个月的高速迭代走向稳定，还要时间验证；但"作品即智能体工作区"这个 Agent Native 的产品范式，值得每个做 AI 创作工具的人认真看一遍。
