先说结论：麦田是我最近看过的、对「自动化边界」理解最清醒的一个国产开源项目。它 13 天拿到 2303 Star 不是靠营销，而是切中了一个真实到肉疼的需求，并且在最容易翻车的地方主动踩了刹车。

我把仓库完整克隆下来逐文件读了一遍，还把测试套件真跑了一遍（26 个测试文件、149 个用例，9.2 秒全过）。下面是基于一手核验的评价，不是照抄 README。

一、它解决的问题有多真实？

一个同时运营 B站、抖音、小红书、视频号、YouTube、X、Instagram 的博主，每条视频剪完后，要在七个创作者后台重复七遍「上传、传封面、贴文案、设定时、点发布」。而且每个平台的标题字数、正文风格、封面比例、话题规则都不一样。

更要命的是发完之后：哪期在哪个平台起来了、哪个平台在涨粉、哪个平台真带来了付费，数据散在七个后台，没有统一视图。麦田的作者麦当本身就是做 AI Agent 教程的博主，这套系统是照着他自己每天发视频的流程 dogfooding 出来的，不是 PPT 项目。

二、技术架构：三层拆分，而不是一个大脚本

我本以为这类工具是一个模拟点击的大脚本，实际它把职责拆成了三层，这是它能维护下去的关键。

  • 发布 Skill（装进 Claude Code / Codex）：看片、纠错、为七个平台写差异化文案，生成标准化的 publish.json 并校验。
  • 麦田发布助手（Chrome 扩展，应用商店上架、自动更新）：真正打开上传页、传视频封面、填表单、设定时。把易变的平台适配逻辑放进可热更新的扩展，平台改版时更新一次所有人自动生效，不用动主程序。
  • 麦田 Hub（Node 守护进程，仓库主体）：调度、防重、等你点发布、取链接、采数据、网页大屏、飞书通知。用 Node 22.5 内置的 node:sqlite，数据存本地，不依赖外部数据库。

代码量我数过：src 目录 35 个文件 3529 行，全仓库 JS/MJS 70 个文件 6064 行。功能这么多，体量却很克制。

三、最反直觉的一点：它故意不帮你点「发布」

这是我认为整个项目最有产品判断力的地方。

市面上的群发、群控工具都在喊「全自动、无人值守、一键全发」。麦田反着来：国内的 B站、抖音、小红书、视频号四家，它只把表单填好就停下来，最后那一下发布必须你自己点，守护进程每 20 分钟提醒一次。

我在 config.example.json 里核对了划分：manual（人工）是 bilibili、douyin、xhs、channels 四家国内平台；auto（回读核对后自动提交）是知识站、X、YouTube、Instagram、Threads 五家。

为什么这么设计？因为全自动批量发布恰恰最容易触发风控、导致封号。把「填写」这种重复劳动自动化，把「发布」这个不可逆的高风险动作留给人，是一条能长期用下去的安全边界。README「各平台的坑」里全是这种实战细节：小红书只读已渲染内容、模拟人滚动点击而不调接口；同一条视频每平台只传一次防重；视频号定时可能被平台改掉（作者真遇到过 +2 小时），sync 会比对并告警。

四、它不止能发，还能复盘

麦田用农业隐喻把流程分成三段：播种（分批发布、定时排期、防重）、长势（每天采流量粉丝，新内容头三天每 6 小时采一次抓冷启动）、收成（靠 UTM 追踪注册、会员、订单、收入的来源漏斗）。

它的复盘机制很专业：每期发布后第 1、3、7 天自动出复盘卡片，做「同龄对比」——第 N 天对第 N 天，而不是拿老内容的成熟期欺负新内容；每周一自动出周报。这和一个成熟运营的手动复盘节奏完全一致，只是自动化了。

五、安全模型：不存密码，是这类工具的生死线

能登录你所有账号的工具，信任是第一位的。麦田最关键的一条是不存任何平台密码：它操作一个专用 Chrome，用你自己登录好的登录态（CDP 9333 端口）。我核对了 .gitignore，config.json、data/、chrome-profile/、logs/ 全部不进 git。

它还只读你自己账号的创作者后台，不做互动自动化、不碰别人账号，从根上避开刷量灰产。不用的平台可停用。甚至会校验视频必须 faststart（moov 在文件头），否则小红书报「无视频流」、抖音出不了表单，在 validate 阶段就拦下。

六、上手成本与我的实测

它用三级路径降低门槛：L1 只看数据约 30 分钟、L2 分发再加 1 小时、L3 转化看你自有站点的开发量。环境要求 macOS/Windows 10-11、Node.js ≥ 22.5、Chrome。除了一行脚本安装，还支持「Agent 自动安装」——把一段话丢给 Claude Code，它自己读指引装好本体和 Skill。

关于代码质量，我实跑了测试：node --test tests/*.test.mjs，149 个用例全部通过、零失败、耗时 9.2 秒，覆盖 B站/抖音/小红书采集、飞书通知、小鹅通销售、站点转化、配置管理。对一个 13 天的个人项目，这个测试密度很难得，也解释了为什么 7 个贡献者敢在这么短时间内协作。

七、适合谁，不适合谁

适合：同时运营 3 个以上平台、被重复发布折磨的个人博主和小团队；想要统一数据大屏又不放心把密码交给云端 SaaS 的人；已经在用 Claude Code/Codex、想把发布纳入 Agent 工作流的人；想学「Chrome 扩展 + Node 守护进程 + 本地 SQLite」桌面自动化架构的开发者。

不适合：单平台且更新不频繁的人（这套系统对你过重）；没有一台常开电脑的人（需要常驻）；追求完全无人值守、连发布都不想点的人——它在国内平台刻意不满足这个需求，而这正是它的安全底线。

最后做个客观提示：麦田是 MIT 许可、可自托管，但任何通过浏览器操作真实平台账号的自动化都存在平台规则变化的风险，重要账号建议先用小号验证节奏。它降低的是重复劳动，不是让你无视平台规则。

项目地址：https://github.com/CzzzzzzJ/mdldm-maitian

一句话总结：麦田最有价值的不是它能自动发多少平台，而是它清醒地知道哪些事不该自动化。在人人鼓吹「全自动」的时代，这种克制反而成了最稀缺的产品判断力。
