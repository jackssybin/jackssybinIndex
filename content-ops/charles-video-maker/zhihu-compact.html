文本生成视频现在主要有两条路线：一是 Veo、可灵这类视频模型直接吐画面，优点是零门槛，缺点是抽卡——构图、数字、连续性都不可控；二是 Manim、Remotion 这类代码动画，画面确定但通常需要工程师手写大量代码。charles-video-maker 走的是第二条路线的 Agent 化形态：让编码模型写一个暴露 render(t) 的动画网页，用 Playwright 逐帧截图，FFmpeg 合成 MP4，再配上一条完整的配音、字幕、素材和质检流水线。

仓库地址：https://github.com/anneheartrecord/charles-video-maker ，MIT 协议，2026-10-19 建仓，截至本文 49 Star，本质是一个 Agent Skill（约 2.9 万行脚本与文档，含原样收录的 Anatomy）。作者在 README 给出一组自述数据：用它的抖音模式运营零粉丝新号，2026-10-20 起 13 天总播放 37 万+，最高单条 23.1 万、7053 次分享，0 投流。我克隆仓库读了 SKILL.md、14 份 references 和全部脚本，这篇从工程视角拆解它的流水线，并区分哪些能力是工具提供的、哪些结果仍取决于人。

一、总体架构：一个 Skill 里的四条分流

Skill 的 SKILL.md 首先做路由，而不是假设所有需求都走同一模板：

  1. 1. 代码动画：模型写随时间 t 绘制的页面（Canvas/SVG/WebGL/Three.js/Remotion/Manim），Playwright 逐帧截图后 FFmpeg 合成；
  2. 2. 素材打底：scripts/footage/ 用实录、原视频片段、免版税空镜、生成图垫底，代码层渲染成带 alpha 通道的透明 .mov 叠在素材上；
  3. 3. 机器讲概念：anatomy/ 原样收录 Anatomy，用等距风格把概念造成会动的机械装置（百分表、抽屉柜、发动机），bridge 把静态 SVG/React 图接入逐帧渲染；
  4. 4. 抖音知识号模式：从一条在爆的原片出发的端到端复刻流水线。

Skill 明确写了 Not for：不用 Veo 这类视频模型生成素材、不替代 Premiere/CapCut/AE、不给已有视频加字幕。这条边界很重要——它是"用确定性代码生成画面"的工具，不是通用视频编辑器。

二、渲染主线：render(t) + 并行截图 + FFmpeg

核心思路在 SKILL.md 里说得很直白：Opus 这类模型不直接输出视频，但会写网页；网页暴露 render(t)，脚本按帧率驱动时间参数逐帧截图。scripts/render.py 与 render_parallel.py 负责单帧与并行渲染，bridge/ 提供虚拟时钟、视频叠加层和页面包装，让同一个页面既能交互预览，也能在无头环境按确定时间被截图。

这带来两个工程性质：

  • 可复现：同一代码、同一 t 序列产出同一画面，不依赖生成模型的随机性；
  • 可精修：画面元素、动作时机、显示的数字都能在代码里定位到具体帧修改，质检可以直接检查渲染产物。

竖版默认规格是 1080×1920、30fps，第一帧即封面构图；横版可选 1920×1080、24fps。

三、配音与时间轴：整段合成，Whisper 对回原稿

配音流水线（scripts/voice/）是这个 Skill 区别于简单"截图+配乐"脚本的关键：

旁白稿 → TTS 整段合成（默认 Gemini TTS 1.25×；可选 edge-tts、Kokoro 离线）
       → Whisper 逐字时间戳（Apple Silicon 用 mlx-whisper，其余 faster-whisper）
       → align.py 把识别结果对回原稿 → timeline.py 生成切点、动作点、字幕时间轴
       → mix.py 混音（配乐/音效/旁白）→ audio_tools.py 标准化到 -14 LUFS 并做真峰值检查

关键设计是字幕不直接用 ASR 文本：Whisper 只提供时间信息，显示文本对齐回原稿，因此识别错字不会出现在字幕里；场景切换、画面动作和音效都绑定到"念到哪个词"，而不是拍脑袋估秒数。这对代码动画尤其重要——render(t) 里的动作可以精确跟旁白对齐。

四、三道质量闸门：事实、响度、静止帧

针对 AI 视频最常见的三类事故，Skill 内置了可执行检查而不是口头提醒：

  1. 1. 事实核查（factcheck.py）：稿中出现价格、额度、数据、功能、截止日期或"最新/现在"等时效性表述时，先 extract 建核对表；正式渲染前跑 gate，同时校验旁白文本和页面代码里的数字，退出码非 0 阻止出片。这直接对应"AI 一本正经编数据"的风险。
  2. 2. 音频闸门（audio_tools.py）：混音后标准化到 −14 LUFS（主流平台的投放响度区间），检查 true peak，并输出波形图供人工复核。
  3. 3. 静止检查（still_check.py）：检测画面静止超过 2 秒的段落，以及字幕已更换但画面未跟进的失配——这是判别"幻灯片式假视频"的有效启发式。

此外还有 qa_stills.py 逐场景拼图自检：把关键帧拼成联系表，让 Agent 或人对照 brief 检查构图与内容，而不是逐帧看视频。

五、素材层：当代码动画不够"真"

scripts/footage/ 让成片不必全是插图：

  • record.py：录制网页实机操作；
  • source.py：下载并转写参考/原视频，定位"某一句话"的起止秒数，便于只引用需要的片段；
  • stock.py：按关键词从 Pexels/Pixabay 搜免版税空镜（需要对应 API Key）；
  • genimage.py：生成图补位；
  • compose.py：统一调色，把素材、透明代码层（alpha .mov）和旁白合成，并做素材比例自检。

这套设计承认了一个现实：产品演示、游戏介绍、评论类内容需要真实画面，纯代码插画再精致也替代不了。代码层在这里退为"信息叠加层"（数据标注、要点、示意图），真实素材负责可信度。

六、抖音模式：D-1→D5 的端到端 SOP，以及它的真实边界

最受关注的抖音模式在 references/douyin-remake.md，配套脚本包括 douyin_radar.py、gemini_copy.py、still_check.py、douyin_publish.py、douyin_stats.py、douyin_comments.py：

  • D-1 题材雷达：抓指定话题下正在涨的视频排名，产出 10–20 个选题；
  • D1 蒸馏风格：一比一拆原片的镜头、节奏、配色、字体、代码类型，但不搬内容与素材；
  • D2 资料与文案：Claude 写任务单（查实事实、每句时长上限、画面指示、对标口播），本地 Gemini（Antigravity CLI agy）写旁白/标题/tag，gemini_copy.py check 做硬校验（时长塞不塞得下、是否编数字、标题标签规则），最多返工两轮。作者明确记录了分工原因：Claude 旁白太僵硬，所以"Claude 管事实结构，Gemini 管说法"；
  • D3 先测配乐再排画面：先定音乐与卡点，再设计镜头节奏；
  • D4 制作自查：逐镜头渲染、静止检查、响度与字幕检查；
  • D5 交付与回流：封面 + 仅含标题/简介/5 个 tag 的 publish.txt，定时发布后拉 2 秒跳出、5 秒完播、赞藏分享和评论，写回用户自维护的运营手册。

但必须强调 README 的原话：同一套流水线也做出过几十播放的片子，流量主要由选题和开头 3 秒决定，工具负责把成品质量稳定在同一水平。 工程上它是质量稳定器和产能放大器，不是爆款保证。雷达与复刻方法解决的是"提高命中概率"，发布数据（23.1 万播放那条）是作者单一账号、约两周的自述样本，不能当作使用工具后的承诺效果。另外"复刻爆款风格"在素材与文案上有版权和平台规则风险，Skill 自己的规则也写明参考视频只学结构手法、不照搬素材文案，实际使用需要自律。

七、依赖、协作来源与成熟度

必需依赖：Python 3.9+（numpy/scipy/playwright + Chromium）、FFmpeg、Node.js 20.10+（Anatomy 构建只用内置模块）、Whisper（mlx 或 faster）、TTS（GEMINI_API_KEY 或免费 edge-tts，Kokoro 可离线）。可选：yt-dlp、Pexels/Pixabay Key、登录创作者中心的 Playwright 配置、Lemo 风格库（约 350MB，采样库另约 1.3GB）。所有 Key 只从环境变量读取。

来源归属在 NOTICE.md 里标得很清楚：视频流水线起步于 Kianzzz 的 xilo-opus-video（本仓库加了配音流水线），anatomy/ 原样收录 wheresryan22 的 Anatomy，抖音打法改写自蔚蓝 WEILANX 的教程第五、六章，风格库/真乐器采样/Kokoro/阅读时长检查来自 LemoLab 的 Lemo-Opuscar。协议为 MIT 并保留原作者版权声明。

成熟度上也要客观：项目仅约两周历史、49 Star、0 open issue（更多反映规模而非可靠性），ROADMAP 里视频模型补位、空镜自动打分挑选、原片引用处旁白自动衔接都还没做；抖音模式还强依赖本地 Antigravity CLI 和登录态浏览器。

结语

charles-video-maker 的参考价值不在于"37 万播放"这个结果，而在于它把一句口号变成了工程 SOP：让模型写确定性的 render(t)，用传统图形学管线（截图、FFmpeg、响度标准、字幕时间轴）保证可复现，用事实核查与静止帧检查兜住 AI 内容最容易塌的两处——数字造假和画面偷懒。 配合"Claude 管事实、Gemini 管说法"的文案分工，它展示了多模型 + 传统媒体工具链组合做内容的一种现实形态。如果你要评估能否用于自己的频道，建议先跑通普通模式做一条知识讲解，再决定是否碰依赖账号与合规判断的抖音模式。
