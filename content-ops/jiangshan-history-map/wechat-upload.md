# 7000人Star的中国历史交互地图，零框架纯手写，拖动滑块看两千年江山分合

先问一个读历史时常有的困惑：**苏东坡被贬的黄州、韩愈勒马的蓝关、岳飞北伐的朱仙镇，放在今天地图上到底在哪？长安两千年里换过多少个名字？**

最近有个开源项目把这些问题装进了一张能拖动时间轴的古舆图，叫「江山时序」，GitHub 上 7096 个 Star。它最让我意外的不是题材，而是工程做法——这么数据密集的一个历史地图，居然一个地图框架都没用。我把源码整个翻了一遍，这篇讲讲它怎么做到的。

## 一、先看家底：没有 package.json 的前端项目

现在随便一个前端项目都要先 npm install 装一堆依赖，这个项目根目录里连 package.json 都没有，更没有 node_modules。我数了下：17 个原生 JavaScript 模块、3.4 万多行代码，最大的一个文件上万行，地图投影、SVG 路径、点击命中全部自己写。

![四层架构与零依赖技术选型](/root/jackssybinIndex/content-ops/jiangshan-history-map/media/architecture.png)

数据侧按 18 个历史时期分目录，从战国、秦、汉一直到民国、当代，一共 206 个 GeoJSON 文件、205 个时序快照，数据约 32MB。我特意在代码里确认过，确实没有引用 leaflet、mapbox、d3 这些常见库——双击 index.html，整个应用离线就能跑。部署也简单到三行 Docker 配置，nginx 托管静态文件而已。

## 二、四种玩法，把历史课本变成可交互的舆图

第一种是**拖时间轴看天下分合**，也是最震撼的。拖动滑块，战国七雄、三国群雄、宋辽西夏金的并立政权在同一张图上用不同颜色呈现；切到重大事件时，新版图出现，上一阶段的疆域会留下朱砂色虚线残影，盈亏一目了然。时间轴上方还同步显示当年的皇帝和年号，黄河改道、罗布泊消长、历代长城运河都会跟着年代变化。

![四种交互玩法](/root/jackssybinIndex/content-ops/jiangshan-history-map/media/gameplay.png)

第二种是**点地溯源**。点任意一座古城，弹出它从战国的郡、汉代刺史部、唐代的道、宋代的路，一路到现代省市的沿革表，本地发生过的大事按朝代列好；函谷关、玉门关这些名关还有专门的城楼图标。

第三种是**点人溯事**。搜一个人物，地图用编号图钉标出他一生的足迹，年份和版图跟着脚步走。内置了秦始皇、张骞、诸葛亮、玄奘、李白、苏轼、王阳明七个人，还能同时搜"李白 杜甫 高适"看他们在哪相逢。

第四种是个**寻址测验**：隐去城名，只给当朝线索让你盲猜落针，按距离打分，最后封你个"太史令""职方郎中"，寓教于乐。

## 三、数据模型：一个疆域快照里装了什么

这个项目最见功夫的是数据组织。我打开快照文件看了结构。

![快照数据模型与压缩巧思](/root/jackssybinIndex/content-ops/jiangshan-history-map/media/data-model.png)

每个时间切片里，`caption` 是年代标题，`note` 是一段完整的史事考辨文字，政权、疆域、政区分别用数字 ID 索引关联。比如 648 年那个快照，就详细写了阿史那社尔平龟兹、置安西四镇和王玄策破中天竺的来龙去脉。它不是给你看一张色块图，而是把"为什么这样划界"讲清楚了。

为了让 32MB 数据在静态站里跑得快，作者用了几个很硬核的压缩技巧：地理坐标用每字符 5 位的自定义编码，存经纬度增量而不是绝对值；相同几何形状做特征缓存复用；GeoJSON 按朝代拆分按需加载；连网页字体都只加载实际用到的字。这些都是专业 GIS 才会考虑的优化。

## 四、每个历史瞬间，都有一个可分享的网址

还有个很实用的设计：你看到的每个画面都反映在网址里。`?year=208&place=赤壁` 直接定位赤壁之战，`?person=sushi` 打开苏轼的贬谪路线，甚至能传一串年份和地点，把"黄州惠州儋州"画成一条路线。加个参数还能变成嵌入模式，老师做课件、博主写文章，直接把精确到年份的地图插进页面里。

## 五、祛魅：一个个人项目的可信边界

![价值与能力边界](/root/jackssybinIndex/content-ops/jiangshan-history-map/media/limits.png)

喜欢归喜欢，几条边界得说清楚。

首先它是个人数字人文作品，**疆域边界是示意性的，不是精确国界**——古代政权的实际控制线本来就难还原，做严肃研究还是得回去查《中国历史地图集》这种原始文献。其次各朝代快照密度不均，战国、唐、清切得细，有些时期相对粗。

协议是 **GPL-3.0 而不是 MIT**，这个对开发者很重要：它有强传染性，你要是把它整合进自己的项目分发，衍生作品通常也得开源；只是自己学习或 iframe 嵌入则没影响。另外它没有后端，史料修正全靠 GitHub 提 PR。

## 写在最后

这个项目打动我的，是它用一种很"古典"的方式做现代数据可视化：不追框架、不堆依赖，靠严谨的数据建模，把两千四百年的政权更迭和人物行迹，做成一个能探索、能引用、能离线运行的整体。那些写进每个快照的考辨文字、虚线残影的盈亏表达，都说明作者真正在乎的是帮人建立时空直觉。

对历史爱好者和老师，它是难得的直观教具；对前端开发者，这个零依赖自研 GIS 也是研究几何压缩的好样本。只是记住，它是带你走进历史的门，不是替代原始史料的结论。
