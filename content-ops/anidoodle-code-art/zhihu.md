# 读完 anidoodle 的确定性契约：为什么说它把 AI 画画拉回了软件工程的轨道

生成式 AI 画图有一个绕不开的特性：同一套提示词运行两次，得到的是两张不同的图。对于单张海报，这种概率性也许可以接受；但当你要制作一部上千帧的短片、维护一套需要长期统一的品牌视觉时，"每次都重新掷骰子"就成了工程上的不可控因素。最近我读到一个 1703 Star 的开源项目 [anidoodle](https://github.com/alexgreensh/anidoodle)，它对这个问题给出的答案相当彻底：不让模型直接输出像素，而是让模型写出一段确定的绘图代码。

它的口号是"手绘的艺术，用代码写成"。每一笔是一个函数，每一个音符是一次算术运算，于是同一份源码在任何机器、任何尺寸下都会重新画出同一张画。我把它约 8.1 万行的引擎和那份极其较真的确定性契约完整读了一遍，这篇文章谈三件事：它的技术路线和传统图像模型差在哪、可复现性是如何被强制保证的，以及这套思路的边界。

## 一、产品形态：Agent 技能，而非独立软件

首先要澄清定位。anidoodle 不是带界面的绘图应用，也不是一个新模型，而是一个标准的 Agent 技能文件夹，分别提供 Claude Code、Codex 和 Grok Build 的插件清单。真正编写代码的是用户的编码 Agent，anidoodle 提供的是方法论、绘图引擎和质量门禁。

从代码规模看，它绝非演示项目：引擎包含 1139 个 TypeScript 文件、约 8.1 万行代码，tools 目录下有 84 个工具脚本，测试目录包含 89 个测试文件。安装后用自然语言描述需求即可，例如"给招聘页面画一张孔版印刷风格的灯塔，1600×900"，系统会自动把请求路由到对应工作流和风格配方。

## 二、核心思想：把一帧画面定义为纯函数的一次求值

理解 anidoodle 的关键，是区分"生成艺术"与"生成式模型"这两条路线。

![代码作画与传统图像模型的确定性对比](media/concept.png)

用图像模型逐帧生成视频，每一帧都要调用一次模型、消耗一次 token，而且帧与帧之间的风格和角色很容易漂移。anidoodle 让 Agent 一次性写出一个纯函数绘图引擎，此后所有渲染都在本地完成、不再调用模型，也就没有后续成本。README 中的示例短片长 47 秒、共 1410 帧，它本身就是一个程序：第一遍写作时大约每帧花 60 个 token 的代码量，之后在任何机器、任意尺寸下重新渲染全部画面和立体声配乐都是免费的，并且结果分毫不差。

这个抽象统一了三种产物：静态插画是纯函数被调用一次，循环贴纸是同一个函数被反复调用，短片则是该函数配上叙事结构和配乐。三者共享同一套确定性保证。

## 三、确定性契约：可复现是强制规则，不是营销话术

整个项目最有技术含量的是 determinism-and-contract 这份文档，开篇就写明：如果没有确定性，那不是一部电影，只是一场现场表演。我把核心条款归纳为六条。

第一，`renderFrame(frame, env)` 必须是纯函数，帧之间不携带状态，模块级不允许存在触碰像素的可变状态，音频采样同样是采样率的纯函数。第二，随机数只能来自带种子的 rng，核心代码中永远禁止 Math.random，也禁止 Date 和 performance.now，时间概念只允许存在于宿主层。第三，画布能力受到严格限制，只开放路径、填充、描边、裁剪、变换、合成、渐变和预加载字体的文本绘制，任何形式的 ctx.filter 都被禁用——因为 Safari 不支持它，会破坏跨浏览器一致性；同时禁止直接接触 DOM、window 和动态创建的图像对象。

第四，仓库默认不存放任何图片、字体和音频素材：文字由笔画生成、纹理是带种子的噪声、音乐由算术合成，这让整个仓库就是整部作品，也规避了素材授权问题。仅有的三个例外（vendored 的 three.js、一个 base64 内嵌字体、烘焙的旁白音频）全部通过哈希锁定，依赖不可能在影片构建后悄悄变化。第五，缓存只允许在值是键的纯函数时使用，而且缓存键必须命名该像素依赖的每一个输入；文档还坦白记录了两个靠机器扫描而非肉眼发现的违规——一个标注层的键漏掉了曲柄角度，另一个漏掉了姿势。第六，位图永远只能缩小不能放大，近景必须在对应视角重新着墨。

验证手段同样严格：在不同页面正向和反向哈希探针帧，把冷启动渲染与缓存渲染做对比，标准是视觉一致且 PSNR 高于 45dB，优先使用零成本的哈希相等判断。文档甚至提醒半色调对亚像素位移极其敏感，一次错位就会损失 17dB，这种细节只有真正踩过坑才写得出来。

## 四、32 种画风与 21 种曲风：风格是配方，不是滤镜

![anidoodle 的 32 种手绘风格分类](media/styles.png)

配置文件中确实包含 32 套完整风格配方，覆盖铅笔水彩、马克笔漫画、孔版印刷、木刻浮世绘、水墨、刮画、像素画、玩具积木、低多边形 3D 等。每种风格模拟的不只是最终观感，还包括该媒介真实的落笔顺序：水彩先打铅笔稿再由浅到深铺色，木刻先印主版再逐一套色，像素画先搭纯色形状再加阴影。每种风格都附带按真实作画顺序逐笔生成的延时影片，而且影片最后一帧与静态图像逐像素一致，明确拒绝用淡入淡出伪装作画过程。

音乐侧同样基于代码合成，不使用采样和录音。21 种曲风提供音色、律动与和声词汇，但和弦、动机和曲式每次重新创作；引擎建模了钢琴、电钢、弦乐铜管、吉他贝斯和多套鼓组，以及磁带晃动、黑胶噪音等低保真质感。在任何人试听之前，music check 会先审核调性、响度、掩蔽、声部平衡和新颖度，听起来像已有作品的配乐无法通过。

## 五、工作流与工具链：先静态验证，再规模化生产

![anidoodle 从需求到成片的五步工作流](media/pipeline.png)

它的工作方法强调先用一张静态图验证效果，确认方向后再一路做到底，把人工审批留给出错代价高的节点。84 个工具覆盖完整链路：scaffold 搭建骨架、still 输出静态图、render 渲染 GIF/MP4/带透明通道的 WebM、music 作曲、gate 一次性检查确定性与契约、verify-export 解码校验最终交付文件，emit 则生成一个约 100KB、双击即可离线播放且自带声音的 HTML。

四个渲染后端 playwright、html-player、remotion、hyperframes 共用同一个绘图核心，核心本身不关心调用方是谁。运行环境要求 Node 20 以上，动态内容还需要 ffmpeg。针对产品发布场景，它内置 launch 工作流，一条时间线输出 16:9、1:1、4:5、9:16 四种画幅并分别重新构图，自动生成封面帧与 srt/vtt 字幕，校验音画同步和峰值电平，保证没有文字被边缘裁切。

## 六、边界与工程诚实：比能力更重要的是态度

![anidoodle 的适用场景、能力边界与工程文化](media/limits.png)

理性看待它的边界。它是 Agent 插件而非开箱应用，使用者需要具备编码 Agent 环境，成品的审美上限仍取决于引导质量和底层模型；8 万行引擎的深度定制存在学习曲线，动态渲染依赖 Node、ffmpeg 和浏览器；它的照片重绘是把照片测量为明暗和方向后再用代码笔触重画，产出是风格化作品而不是照片级写实；许可证是带 NOTICE 和署名义务的 Apache-2.0，而非更宽松的 MIT。

但这个项目最打动我的，是它的工程文化。确定性文档专门记录了一次无法解释的首跑失败：全新工作区第一次 gate 报告 0/12 帧全部不一致，之后七次复测又全部通过、无法复现。很多团队遇到这种情况会重跑到绿灯然后沉默，作者却写下完整经过，并断言"一次失败随后通过是最危险的结果，重跑直到变绿然后闭嘴不可接受；一份诚实的'无法复现，这是我尝试过的方法'本身就是结论"。文档中还保留着大量"每条规则都是一次画砸换来的"伤疤注释，例如行注释曾吞掉语句后半段、三次搞挂构建，因此在密集单行代码库中强制使用块注释。

## 结论

anidoodle 的价值并不在于"AI 能画画"这个已经不新鲜的命题，而在于它把生成艺术重新拉回软件工程的轨道：用纯函数、种子随机、哈希锁定和帧级校验，把灵感转化为可复现、可版本管理、可团队协作、可零成本重复渲染的资产。

它当然不是万能的——照片级写实、零门槛开箱、脱离编码 Agent 独立运行，都不是它的目标。但如果你认同"一件作品应该能被一份源码完整重建"，那么 anidoodle 所示范的确定性与工程诚实，正是当下 AI 创作领域稀缺的东西。
