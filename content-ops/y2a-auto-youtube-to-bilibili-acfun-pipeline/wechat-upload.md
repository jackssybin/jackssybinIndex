搬过视频的人都明白：真正折磨人的从来不是下载。

把一个 YouTube 视频搬到 AcFun 或 B 站，完整动作是一长串——想办法绕过反爬下视频和封面，听不懂原文就开 ASR 听写字幕，翻译成中文还得手动断行对时间轴，AI 偶尔写出几句"幻觉字幕"你还得逐句查，再改标题、写简介、选分区、加标签，最后分别登录两个平台传一遍。一条半小时，中途任何一步报错，常常从头再来。

这周我翻到一个开源项目 **Y2A-Auto**（GPL v3，GitHub 3256 星），目标就一句话：**丢一个 YouTube 链接进去，AcFun、B 站自动出稿**。

我把仓库克隆下来通读了源码——109 个 Python 文件、合计 5 万行，光任务调度核心一个文件就 8497 行。这篇不写软文，说清楚三件事：它凭什么叫"系统"而不是脚本缝合、字幕这种最容易翻车的环节怎么兜底、以及用它要承担什么风险。

## 一、骨架是一台带断点的状态机

很多"自动化工具"其实是个几百行的顺序脚本，下载失败、翻译超时、上传断网，任何一步崩了整条重来。Y2A-Auto 不一样，它在代码里把流程显式定义成一条有名字、有顺序、能持久化的阶段链：

取视频信息 → 翻译标题简介 → 生成标签 → 推荐分区 → 内容审核 → 下载视频 → ASR加翻译字幕 → 上传 AcFun/B站。

![Y2A-Auto 的 8 阶段流水线与人工审核插桩点](/root/jackssybinIndex/content-ops/y2a-auto-youtube-to-bilibili-acfun-pipeline/media/02-pipeline.png)

三个细节，能看出作者是真被坑过：

**断点写进数据库，不靠文件。** 每个任务有个 `pipeline_checkpoint` 字段存进 SQLite，记录已完成阶段。注释写得很直白：就算下载目录被清空，断点也不丢。进程意外退出后重启，卡住的任务会被回收成待处理，从上一个完成的阶段接着跑，已经下好、翻译好的东西不浪费。

**先做元信息，后下视频。** 取信息、翻译、生成标签、推荐分区、内容审核，全部排在下载视频之前。最重、最占带宽磁盘的视频，要等"值不值得搬、过不过审"判断完才拉。批量监控时能省掉大量无效下载。

**人工审核默认插在环里。** 无人值守总开关默认是关的。不开自动模式，流水线会在上传前停下，把 AI 生成的标题、简介、标签、分区摆到后台让你逐项改完再发；打开才全自动。对搬运这种容易触发风控的事，默认把人留在环里是对的。

## 二、一个面板管完 Cookie、AI、转码、监控

它用 Flask 在本地起一个 Web 后台，默认 5000 端口，所有配置都在页面上分组管理。

![Y2A-Auto 任务仪表盘](/root/jackssybinIndex/content-ops/y2a-auto-youtube-to-bilibili-acfun-pipeline/media/01-dashboard.png)

真正让它从"单条搬运工具"变成"频道运营工具"的是 **YouTube 监控**。你可以监控指定频道，或用关键词定时搜，只跟最新或连历史一起搬，还能筛选普通视频、Shorts、直播回放，命中后自动入队。

这里有个很专业的设计：它给 YouTube Data API 的每日搜索配额做了预算。搜索每天默认只有一万单位，配额耗尽时只跳过本轮，而且不推进时间游标——这样配额恢复后，不会漏掉跳过窗口里发的新视频。时区还专门做了夏令时感知。

![YouTube 频道与关键词监控页](/root/jackssybinIndex/content-ops/y2a-auto-youtube-to-bilibili-acfun-pipeline/media/03-monitor.png)

## 三、字幕会幻觉，所以它做了三层兜底

搬英文视频，字幕是质量分水岭，也是最容易翻车的地方。Whisper 这类 ASR 偶尔会把背景音乐、界面提示音、口头语"听"成文字，直接烧进画面就很灾难。

它的字幕链路是 ASR 生成 → 翻译 → 质检 → 后处理 → 烧录，质检是**分层**的，不是无脑全扔给大模型：

- 先用规则硬拦截：署名行、噪声提示、界面操作词、模板化重复句，规则层直接判失败，不浪费 AI 调用；
- 只有拿不准的边界样本才送 AI 抽样复核，有分数门槛、抽样条数和字符上限；
- AI 不可用时默认按失败处理，而不是放行。

更关键的是失败后的策略：质检没过，它跳过烧录字幕，但保留字幕文件、继续上传原视频，任务照样完成、只带一个"字幕异常"标记。它选择"宁可这集没中文字幕，也不让整条流水线崩"，返不返工留给人决定。烧录字体仓库直接内置了思源黑体，不用自己找中文字体。

## 四、那些"能跑起来才懂"的脏活，它都做了

读完源码我觉得最值钱的不是 AI，是一堆被现实捶打出来的兜底：

- **AI 接口双兼容**。Chat Completions 和 Responses 两套协议都能接，第三方网关不支持某些参数时，它按报错逐级砍参数重试，最后退化成最小请求，方便你接国产兼容接口省钱。
- **硬编失败自动回退**。默认优先 HEVC 硬编，N卡、Intel、AMD 各有对应编码器，任何一个失败自动退回 CPU 的 H.264。
- **通知用异步重试队列**。企业微信、Server 酱、message-pusher 三个渠道，任务成败、扫码登录、账号锁定都能推，失败按半分钟到一小时递增重试。
- **Cookie 不必手导**。支持接 CookieCloud 自动同步 YouTube Cookie；AcFun、B 站直接手机扫码登录。
- **安全不裸奔**。Web 密码保护、错五次锁十五分钟、会话超时、随机密钥、路径遍历防护都有；官方还专门提醒别把 5000 端口裸开公网，云服务器用 SSH 端口转发访问。

## 五、五分钟跑起来

官方推荐 Docker，不用自己装 Python、FFmpeg、yt-dlp：

克隆仓库，把 YouTube、AcFun、B 站三份 Cookie 放进 cookies 目录，`docker compose up -d`，打开本地 5000 端口。配置、数据库、下载、日志都会持久化到本地。

第一次进后台的正确顺序：先开登录保护 → 扫码登录两个平台 → 放好 YouTube Cookie → 填 AI 的地址和模型 → 需要字幕就开 ASR 和翻译 → 先手动提交一条试跑，确认没问题再考虑打开全自动和监控。

## 六、谁该用，谁先等等

**适合**：做海外内容译介、有授权或合理使用需求、需要批量加中文字幕、希望人工审核和无人值守自由切换的运营；愿意自己管服务器、Cookie、API 成本的技术玩家。光看它的状态机和质检分层，也很值得抄。

**先等等**：纯原创 UP 主，这工具对你没用；不愿碰账号 Cookie、对封号零容忍的人；没 GPU 又想批量压 1080p 长视频的人。

**必须自己算清的账，源码替你兜不住**：

一是版权。项目默认帮你加转载声明，简介自动追加"本视频转载自 YouTube，原始时间和 UP 主"，这是好习惯，但**声明不等于授权**，能不能搬取决于原作者许可、平台规则和使用性质。

二是风控。自动上传和 Cookie 登录在各平台都是敏感行为，建议小号先试、控制频率、保留人工审核。

三是成本。ASR、翻译、质检、生成元信息都调外部大模型，批量跑 Token 不便宜。

## 结语

它让我欣赏的地方，是没把"自动化"理解成"写个定时脚本"，而是老老实实处理了状态、失败、质检、配额和降级——这五样恰恰是工具能不能长期挂着跑的真正门槛。

但工具越自动，人的责任越不能自动消失。它把"怎么搬"做到了工业级，可"该不该搬、拿到授权没、会不会伤到账号"，永远要你自己回答。

项目地址和完整部署文档我放在了「**阅读原文**」，源码、Docker 镜像和 Telegram 试用机器人都能在仓库里找到。
