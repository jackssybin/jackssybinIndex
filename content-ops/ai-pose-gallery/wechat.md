用 AI 画图最折磨人的，往往不是模型不够强，而是找不到合适的参考图。

你想让角色摆出特定姿势、穿上指定衣服、还得保持同一张脸，光靠文字提示词基本靠运气。而高质量的人体素体、服装、人像素材，原本散落在三个独立的日文网站上，标签全日文，找图、下载、再喂给生图工具，每一步都是断的。

最近 GitHub 上有个项目专门把这条链接上了，叫 ai-pose-gallery-zh，一个把姿势、服装、人像三个日文图库完整汉化、还做成 AI 角色合成工作台的中文项目，7869 Star。我把整个仓库（约 1.2GB）克隆到本地逐层拆了一遍，先说结论：**它不是又一个图片收藏夹，而是一套"一份数据、五端复用"的完整生产工具。**

## 先核验家底：README 的图片数字有水分

这个项目 README 信息很密，但我没直接照抄它的合计数，而是逐个打开 JSON 和图片目录重新数了一遍。

三大主库的记录数是准的：姿势 1439 条、写实服装 1407 条、人像 1499 位。另外还有动漫服装 1320 条、中国历代服装 57 套（227 个视角）、二次元 CharaDB 440 套。

![实测数据规模：逐个 JSON 和图片目录核验](/images/ai-pose-gallery-zh/02-data-scale.png)

关键出入在图片计数。README 顶部说本地有 12022 张图，但我实际数 `img/` 和 `thumbs/` 两个目录，**各是 6011 张**。拆开看：白模 1439、深度图 1439、写实服装 1407、历代服装 227 视角、人像 1499，加起来正好 6011。所谓 12022，是把原图和缩略图重复相加了——它们是同一批素材的两种尺寸。更准确的说法是约 6011 张原图、配套 6011 张缩略图。

还有个细节：动漫和二次元服装这两类，仓库里只存元数据、不存图，图片走原站热链，这是它能把体积压到 1.2GB 的关键。

三库的中文检索也做得比较细。姿势库按全身标准、全身性感、上半身、双人缠绵四大体系，再分 26 个动作分类、5 种视角（正面、斜前、侧面、背面、俯视），支持按姿势分组或逐张浏览两种模式；服装库有 8 大穿搭分类和 86 个中文细节标签，每个标签还附了英文 Prompt 关键词，方便你直接搬到生图工具；人像库则按正脸参考、造型氛围两个分区，配合 4 种发长和 51 种细分发型筛选，还有热门榜单。这套中文标签体系是整个项目最耗时、也最有价值的部分，因为它把日文站点原本对中文用户封闭的检索能力打开了。

## 同一套数据，怎么长出五种用法

理解这个项目，最好的角度是看它的架构。底层只有一套静态资产：`data/` 里的全中文 JSON 加上 `img/`、`thumbs/` 里的图片。在这之上，长出五个互不依赖的消费端。

![一套静态资产，五个消费端复用的架构](/images/ai-pose-gallery-zh/01-architecture.png)

一是 React 网页合成台，二是 Cloudflare 边缘代理，三是 ComfyUI 原生插件，四是九个 Agent 技能，五是能整体下载自托管的离线数据集。普通素材站只解决"看图"，它解决的是"检索、组合、生图、接入工作流、进 Agent 上下文"整条链。

这里面我最欣赏的是它的汉化方式。它没有靠人肉逐条翻译，而是用一份日译中词典加 `translations.csv`（实测 474 条对照，比如"2人絡み"译成"双人缠绵"），再用脚本一键生成所有中文 JSON。翻译被做成了可重跑的构建步骤，上游一更新，重新跑一遍就行，这才是一个人能维护六千多条数据的真正原因。

## 合成台和五大生图通道

网页端用 React 19 + Vite 8 + Tailwind 4 搭成，核心是合成页：人像、服装、姿势三个槽位，姿势还能在素体白模和深度图之间一键切换，再支持拖拽、剪贴板粘贴任意张附加参考图。

它内置 12 种画风，从写实写真、二次元、新海诚风到 3D 手办、赛博朋克都有，能根据你选的素材自动组装中英文提示词，再用 Canvas 实时拼出一张 1800×1200 的参考拼图。生成历史存进 IndexedDB 而不是 localStorage，避开了浏览器 5MB 的容量限制。

生图通道直接接了五个：Google Gemini、OpenAI GPT Image、阿里通义 Qwen、字节豆包 Seedream，还有本地 ComfyUI。千问、豆包这类接口浏览器直调会跨域，它就用 Cloudflare Workers 写了个同源代理 `/api/proxy`，还带域名白名单防滥用——这是个很实在的工程细节。

跨页面后台生图这个设计也值得一提。你在合成台提交任务后切到别的页面，请求不会中断，结果回来自动存进 IndexedDB，下次打开还能复用提示词和原图，不用重新组装。本地 ComfyUI 那条链路更完整：它能把三合一拼图和单张素材通过 `/upload/image` 传到你本机的 ComfyUI，再往工作流里注入占位符或自动识别 CLIPTextEncode、KSampler、LoadImage 这些节点，提交 `/prompt` 队列后轮询把成品图取回来，也支持导入导出通用的 `.api.json` 工作流模板。等于把网页的选图体验和 ComfyUI 的专业出图能力缝在了一起。

## 三种上手姿势，按你的工具链选

![同一个仓库的三种上手姿势](/images/ai-pose-gallery-zh/03-three-usage.png)

最轻量的是网页，直接用在线演示，或者本地 `pnpm install && pnpm dev`，零门槛选图出图。

进阶的是 ComfyUI 节点。我读了插件源码，确认它真注册了四个节点：姿势、服装、人像、三合一配方，能在画布里直接输出 IMAGE 张量和中英文 Prompt，姿势节点带深度图开关，可以直接接 ControlNet Depth。装法就是把仓库 clone 到 `custom_nodes` 目录重启，不用额外装 Python 依赖。

最自动化的是 Agent 技能。九个 SKILL.md 软链进 skills 目录后，AI 就能按分类、视角、发长帮你检索素材、返回图片路径，适合做批量角色生产。注意要软链不要复制，因为技能靠相对路径读 `img/`。

代码体量我也数了：前端 67 个 ts/tsx 共 11841 行，插件 1610 行，数据脚本 1342 行，是个有真实工程量的项目。

它的数据脚本也挺成体系。`download.py` 支持按数据集分别拉取、断点续传，已存在的文件自动跳过，还能用环境变量把并发线程调到 64，把 1.2GB 素材的初始化时间压下来；`verify.py` 会校验本地一万多张图的存在性、文件大小和文件头，防止镜像下载出现残缺。对这种以数据为核心的仓库，这种完整性校验往往比业务代码更关键。测试目录里还有专门校验 GPT Image 协议输入保真度的用例，说明多协议适配不是简单封装了事。

## 用之前，合规边界必须清楚

这个项目含部分 18+ 人体素体和性感穿搭，所以有几条得提前讲明白。

![合规边界与适用判断](/images/ai-pose-gallery-zh/04-compliance-verdict.png)

第一，代码协议和图片版权是两回事。GitHub 把它的 license 识别成 NOASSERTION，因为代码是 MIT，但 `img/`、`data/` 里的图片不被 MIT 覆盖，版权归原作者 ギア 和 たき AI，明确禁止打包倒卖。

第二，成人向分类默认被 SFW 安全模式隐藏，未成年人被要求不得解锁，但这只是软件开关，使用环境还得自觉。

第三，它是纯前端、不收集你上传的图，但反过来，未经授权用真人照片做换脸深伪，法律责任全在使用者自己。
