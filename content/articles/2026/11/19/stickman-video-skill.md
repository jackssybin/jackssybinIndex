无脸视频（faceless video）这门生意，最大的门槛从来不是创意，而是重复的制作劳动：写脚本、配音、配图、做动画、对字幕、配音效，一条几分钟的视频能耗掉一个晚上。最近有个叫 [stickman-video-director](https://github.com/kaomei/stickman-video-director) 的开源 Skill 专门解决这件事——把一篇文章或一个话题，交给 AI Agent 自动做成火柴人动画视频，GitHub 上 6972 Star。

和以往只读 README 不同，这次我先把它真正装进了本机、跑通了官方自检和项目初始化，这篇就基于一手实测来讲：它的双引擎是什么、14 种画风怎么选、本地渲染这条链路怎么跑，以及它的真实边界。

## 一、先看家底：一个 556MB 的"导演方法论 + 渲染器"

很多人以为 Skill 就是一段提示词，这个项目完全不是。我把它安装到 `~/.hermes/skills/directing-stickman-videos` 后实测，整个技能有 556MB，拆开看构成很说明问题：

![双引擎心智模型与共同底座](/images/stickman-video-skill/engines.png)

- **73 份 references 契约文档**：每种画风的视觉语言、字幕字体位置、镜头节奏、音效规则、验收标准，全部写成 Agent 必须遵守的 Markdown，而不是藏在代码里；
- **57 个可执行脚本**：统一入口是 `scripts/autopilot.mjs`，下挂渲染、字幕对齐、B4/B5/B6 各风格专用运行时、音效库管理等模块；
- **47 个测试文件、485 项断言**：这在同类 Skill 里相当罕见，说明作者把"防止 Agent 偷工减料"当成了硬约束；
- **253MB 本地音效库**（`assets/b-audio-library`）：B 模式的环境音、动作音效可以完全离线获取，不依赖外部订阅。

它的运行时依赖很轻：Node 20 以上、FFmpeg/FFprobe、`@napi-rs/canvas` 和 `sharp` 两个图像库，外加 5 个 OFL 开源字体。我在 Node v22.22 上 `npm install` 只装了 11 个包，然后跑官方的 `node scripts/autopilot.mjs doctor`，七项检查——node、ffmpeg、ffprobe、canvas、sharp、字体、B4 钩子字体——**全部返回 true**。

## 二、双引擎：最容易被误解的核心设计

这个 Skill 最关键的认知，是它有两条完全独立的制作路线，名字里都带"引擎"，但产物、成本、契约都不一样。

**A · 模型引擎（A1–A7）** 本质是"导演 + 提示词工程"。Agent 负责确认故事、风格、画幅、时长和声音方案，输出分镜和一段段**独立可用的视频生成提示词**，然后可选地通过内置浏览器去操作 Google Flow 这类 AI 视频服务，先用最低分辨率试片、你确认后再连续制作剪辑。它的默认交付停在提示词，是否烧外部额度由你授权决定。

**B · 代码引擎（B1–B7）** 才是真正的本地自动成片。它用 canvas 画插画和微动画、本地 TTS 出旁白、按语音对齐字幕、混入本地音效，最后用 FFmpeg 在你自己机器上渲染成 MP4，全程不上传素材。我实测初始化一个 B1 项目，`autopilot.mjs init` 会在 Skill 之外生成 `project.json` 脚手架，并明确提示"先补充旁白、字幕和场景再渲染"，而不是假装一键出片。

这里有个作者反复强调、我认为最专业的点：**A 和 B 只共享安装，不共享生产契约**。A 的片段时长规则、声音画像不能搬到 B，B 的本地渲染约束也不能套给 A；每个 B 风格还各有独立规则，文档明确禁止"缺工具时偷偷回退到 Gemini、ElevenLabs 或系统 TTS"，做不到就如实降级并说明，绝不伪造通过。

## 三、14 种画风：不是皮肤，是 14 套独立生产规范

技能内置 A、B 各 7 种、合计 14 种画风。我把 references 目录逐个对照后，整理成下面这张图。

![14 种画风全景与 A/B 分组](/images/stickman-video-skill/styles.png)

A 模式从 A1 经典黑白、A2 现代潮酷、A3 史前洞穴、A4 治愈故事、A5 历史卡通、A6 暖金暗影，到 A7 橡皮管动画（Rubber Hose）；B 模式则是 B1 极简线稿、B2 彩色手绘、B3 复古电视、B4 求生短剧、B5 角色解说、B6 动感 Meme、B7 像素剧场。

它们的差异远不止配色。举几个我在契约文档里看到的硬规则：B1–B4 字幕最多一行，B5 允许最多三行语义字幕；B4 求生短剧要求每个镜头和静止画面状态不超过 3 秒、有专门的前三秒视觉升级门禁和恐怖可见度门禁；B6 动感 Meme 竖屏 9:16 效果最好，配有一份 35 项验收矩阵和角色绑定契约；B7 像素剧场走纯代码像素画，不需要任何图像生成服务。技术实现上 B1–B4 共用一个清单渲染器但规则独立，B5、B6、B7 则各自有专用运行时，全部原生支持 16:9 和 9:16 两种画幅。

换句话说，选风格不是挑模板，而是选定一整套"画面怎么画、字怎么摆、几秒切镜、配什么声音、怎么算合格"的规范。

## 四、B 模式本地出片的六步链路

我顺着 `autopilot.mjs` 和 `autopilot-core.mjs` 的源码，把代码引擎这条链路理了一遍，并实际验证了前两步。

![B 代码引擎本地出片六步流程](/images/stickman-video-skill/workflow.png)

1. **doctor 自检**：确认 Node、FFmpeg、canvas、sharp、字体等环境，缺什么会明确告诉你怎么补，而不是跑到一半报错；
2. **init 建工程**：在 Skill 目录之外生成项目，`project.json` 存阶段、指纹、审批状态和断点，保证中断后能续做；
3. **脚本与旁白**：Agent 写剧本，TTS 生成一条连续语音轨——文档要求先有声音再定画面，而不是反过来让语音迁就画面；
4. **语义字幕**：用 `align_captions.py`（可选接本地 Whisper）按真实停顿和语义分组，明确反对按固定字数机械切分；
5. **本地渲染**：canvas 绘制关键帧和微动画，微动画必须推动语义（手敲、物体随台词入场），单纯全局缩放淡入淡出不算动画，再由 FFmpeg 合成；
6. **验收交付**：输出 MP4、SRT/VTT 字幕、联系表和校验报告，而且要求 Agent 用正常速度带声音实际看一遍成片，技术检查通过不等于创作验收通过。

工程上还有几个让我有好感的设计。渲染器**只读声明式 JSON，绝不执行素材里夹带的代码、shell 片段或 URL**，从机制上防提示注入；镜头缓存用内容寻址，渲染中断可以续渲不重复劳动；通常画面静止不超过 2.5 秒，逼作者保持信息密度。我在本机还补装了 B6 需要的 Python 3.11 依赖（numpy、Pillow、opencv），跑 `doctor --style B6` 时 B6 的三项专项检查也全部通过。

## 五、理性看待：适合谁，以及别期待什么

![能力边界与适用人群](/images/stickman-video-skill/limits.png)

**它真正擅长的**，是无脸 YouTube/短视频频道的批量制作、知识解说、故事、Meme 和像素短剧这类"旁白驱动 + 图形化表达"的内容；对想要可复现、不依赖云端、能本地化交付的团队，以及本来就用 Claude Code/Codex 的创作者，契合度很高。

但边界必须讲清楚：

- **它不是一键傻瓜软件**。整个流程靠 Agent 驱动，需要你会用编程类 AI 工具、看得懂它的审批门禁，纯小白会有学习曲线；
- **A 模式要花外部额度**。模型引擎依赖 Google Flow 等视频服务，API key 走环境变量、按用量计费，技能本身不附赠订阅；
- **TTS 与生图要自己配**。它不绑定某个配音供应商，缺适配器时按文档应实现项目级小适配，而不是等它万能兼容；
- **体量和环境门槛真实存在**。556MB 里音效库就占 253MB，B6 还要单独准备 Python 3.11 的科学计算栈；
- **风格契约非常严苛**。每个 B 风格有独立验收矩阵，不允许跨风格偷懒或降级，这保证了下限，也意味着不能指望它"随便点点就出爆款"。

## 我的判断

这个项目最打动我的，是它没有把"AI 自动生成"当成偷工减料的借口，反而用 73 份契约、485 项测试和一道道实际成片评审门禁，把一个成熟导演的工作方法固化成了 Agent 可执行的流程。它诚实地告诉你哪些能本地自动化、哪些必须你授权花额度、哪些做不到就明说而不是伪造结果。

如果你已经在用 Claude Code 或 Codex，又想做无脸解说、知识动画这类内容，它值得装进工具箱，从 B1 极简线稿这种本地零成本路线起步试手；但请记住它的定位——它是一个能力很强的导演副驾，方向盘上的选题、脚本和最终验收，始终在你手里。
