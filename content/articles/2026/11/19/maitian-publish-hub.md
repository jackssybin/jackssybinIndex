一个人做内容，最磨人的不是拍视频，而是发视频。同一期内容要在 B站、抖音、小红书、视频号、YouTube、X、Instagram 上各发一遍，每个平台标题字数、封面比例、文案格式都不一样；发完还得挨个后台看哪期起来了、哪个平台涨粉、哪个渠道真的带来了付费。最近有个叫 [麦田](https://github.com/CzzzzzzJ/mdldm-maitian) 的开源项目，专门解决这件事，建仓才 5 天就拿到 1355 Star。

它和常见的"一键群发"工具最大的不同，是对账号安全极度克制。我把仓库克隆下来逐个文件读了一遍，还跑通了它的演示模式，这篇讲清楚它的三件套怎么协作、为什么敢让它碰你的账号，以及一个 5 天新项目的真实边界。

## 一、先看家底：2400 行代码的个人工作台，不是重型 SaaS

麦田不是一个云端服务，而是跑在你自己一台常开 Mac 上的本地工作台。我统计了代码：`src/` 下 23 个 ES Module，核心约 2400 行，最大的 `hub.mjs` 守护进程 471 行，外加一个发布 Skill 和一个独立的 Chrome 插件。技术栈非常克制——纯 JavaScript ESM，用 Node 22.5 内置的 `node:sqlite` 做存储，没有重型框架，`package.json` 里几乎零运行时依赖。

![麦田三件套的分工与发布链路](/images/maitian-publish-hub/architecture.png)

它的设计分成清晰的三件套：**发布 Skill** 让 Claude Code、Codex 这类 AI 助手看片、为每个平台写适配文案、生成发布工程并做校验；**麦田发布助手**是上架 Chrome 应用商店的插件，里面是各平台适配器，负责打开上传页、传视频和封面、填文案、设定时；**麦田中控**（本仓库）则管分发计划、调度、防重、等你点发布、取链接、采数据、网页大屏和飞书通知。

完整链路是：成片 → Skill 写一份「发布素材.md」→ 生成标准化的 `publish.json` → `hub plan` 进分发计划 → `hub run` 分批填写 → 国内平台你手动点发布 → 到点取链接 → 每天采数据 → 大屏和飞书卡片。这个分工的巧思在于：平台改版时只需更新一次商店插件，所有用户自动生效，中控本体不用动。

## 二、四道安全设计：为什么敢让它操作你的账号

这是整个项目最值得讲的部分。自动化发布工具最大的风险是账号被封，麦田的思路是把"自动化"严格限制在低风险环节。

![麦田的四道账号安全设计](/images/maitian-publish-hub/safety.png)

**第一，不存密码。** 它不要求你填任何平台账号密码，而是驱动一个你自己登录好的专用 Chrome（通过 CDP 9333 端口），登录态保留在本地 `chrome-profile` 里，且这个目录默认不进 git。中控只操作浏览器，永远接触不到你的凭证。

**第二，人机分界。** B站、抖音、小红书、视频号这国内四家，工具**只负责填写和核对，填好就停，最后一下"发布"必须你自己点**，守护进程每 20 分钟提醒一次；而 X、YouTube、Instagram 和自有站点，在回读文案和定时确认一致后才自动提交。把最容易触发风控的动作留给人，是很务实的取舍。

**第三，防重与低频。** 同一条视频每个平台只上传一次——反复重传正是平台风控的高危行为，库里已到位的平台不会再跑。小红书更是只走最保守的路：只读页面已渲染的内容、像真人一样滚动点击，不在页面里直接调接口。视频号这类容易掉登录的平台，还会定时刷新保活。

**第四，本地与权限。** 数据库、日志、登录态全在本机；网页大屏所有页面和接口没有口令一律返回 401，远程访问可以用飞书验证码登录或加一层 Cloudflare Access。它只读写你自己账号的创作者后台，不做互动自动化、不碰别人账号，本体也不上报任何数据。

我还在 `validate.mjs` 里看到一个很实战的细节：它会读成片文件头，检查 `moov` 原子是否在 `mdat` 之前，也就是强制 **faststart**——否则小红书会报"无视频流信息"、抖音不出表单。这种从真实踩坑里长出来的校验，比泛泛的"支持多平台"有说服力得多。

## 三、播种、长势、收成：一套创作者数据闭环

发布只是入口，麦田真正想做的是让一个人也能像团队一样复盘数据。

![麦田的三阶段数据闭环与复盘能力](/images/maitian-publish-hub/data-loop.png)

它借用农业隐喻分了三阶段。**播种**是发布：读 NAS 上的一期发布工程，按批次填七个平台，国内两两一批避免抢带宽超时，定时并自动取链接。**长势**是流量与粉丝：每天上午采一次各期播放互动和各平台粉丝，新一期头三天加密到每 6 小时一次。**收成**是转化（可选）：接上你自己的站点后，靠发布链接上的 `utm_campaign` 参数，追踪注册、会员、订单、收入具体来自哪一期、哪个平台。

数据落在本地 SQLite 的 11 张表里——episodes、tasks、metrics、samples、site_campaigns 等，长期留存可回溯。复盘是自动的：每期发布后第 1、3、7 天出复盘卡片，做"同龄对比"（第 N 天只和第 N 天比，避免拿老视频欺负新视频），还有各平台占比、互动率、期间涨粉，每周一自动出周报；网页端有转化漏斗（播放→注册→会员→收入）和排期日历，飞书群则用带颜色的卡片推送开跑、到位、异常、待发布等所有状态。甚至有 iPhone 桌面小组件，常驻显示全平台粉丝和今日涨粉。

## 四、三级上手：从只看数据到全链路

项目给了清晰的上手梯度，降低了尝试门槛。**L1 只看数据**：装上中控、在专用 Chrome 登录各平台，用 `hub adopt` 登记已发作品，30 分钟就能拿到粉丝监控、大屏和飞书日报。**L2 分发**：再加 Chrome 插件和发布 Skill，实现一期填七个平台、定时、自动取链接，约再花 1 小时。**L3 转化**：按 `src/site.mjs` 的接口接上自有站点，打通收入归因。一行安装脚本会把中控、插件、Skill、开机自启都配好，也可以先跑 `node src/demo.mjs` 用假数据看大屏效果——我在本机实测这条命令能正常起服务并生成演示数据（Node 22.22 满足要求，仅提示 SQLite 是实验特性）。

## 五、祛魅：一个 5 天新项目的真实边界

![麦田的适用人群与能力边界](/images/maitian-publish-hub/limits.png)

喜欢归喜欢，几条边界必须讲清楚。

**第一，平台与环境门槛。** 它主打 macOS，Windows 是社区贡献版，开机自启还没适配，只能用任务计划程序兜底；你还需要一台常开的机器和一个专用 Chrome。核心的平台填写逻辑在 Chrome 商店插件里，不在本仓库，想完全离线审计得连插件一起看。

**第二，成熟度。** 仓库 2026-11-14 才建仓，版本 0.4.0，我没有在 `src` 里找到单元测试文件，质量主要靠作者自己发了几十期视频的实战和 GitHub issue 迭代；它的能力高度依赖各平台页面保持稳定，一旦某个平台改版，要等插件更新。

**第三，它不创造内容。** MIT 协议下你可以自由使用和二次开发，但麦田解决的是"重复填写"和"数据散乱"的效率问题，不是选题、脚本和镜头。能不能起号、能不能变现，最终仍取决于内容本身——这一点 README 里作者也很坦诚，它就是照着自己每天的发布流程一点点搭起来的工作台。

## 我的判断

麦田最打动人的，是它对"自动化边界"的清醒：不碰密码、不替你点国内平台的发布、不做互动刷量，把 AI 和脚本放在提效环节，把高风险决策留给人。在一个充斥着"一键群发、暴力起号"工具的赛道里，这种克制反而让它更适合长期经营账号的正经创作者。

对一人运营多平台、又看重账号安全和数据归因的个人博主和小团队，它值得现在就用 L1 模式试起来；但请接受它是个年轻项目，把它当趁手的工作台而非黑箱，关键发布动作保持自己把关。
