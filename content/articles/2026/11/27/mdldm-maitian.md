我克隆麦田（mdldm-maitian）这个仓库的时间是 2026 年 11 月 27 日，它在 GitHub 上的创建时间是 11 月 14 日——也就是说，这个项目从出生到现在只有 **13 天**，却已经有 **2303 个 Star、598 个 Fork、7 位贡献者**。

一个两周的个人项目，凭什么涨得这么快？我把仓库完整克隆下来逐文件看了一遍，还把它的测试套件真跑了一遍。结论是：它切中的痛点足够普遍，而它对「自动化边界」的克制，才是真正让我愿意写这篇文章的原因。

## 它解决的是每个多平台博主都懂的痛

如果你同时在做 B站、抖音、小红书、视频号、YouTube、X、Instagram，你一定懂那种感觉：一条视频剪好了，真正的体力活才刚开始。

![一期视频要在七个平台手动发七遍](/images/maitian/01-pain-vs-maitian.png)

每个平台的标题字数限制不同、正文风格不同、封面比例不同、话题标签规则也不同。你要打开七个创作者后台，重复七遍「上传视频、传封面、贴文案、设定时、点发布」。更让人焦虑的是发完之后：哪一期在哪个平台起来了？哪个平台在涨粉？又有哪个平台真的带来了付费？这些数据散落在七个后台里，没有一个统一的地方看。

麦田的作者麦当是一位做 0 基础 AI Agent 教程的博主，这套系统不是凭空设计的，而是照着他自己每天发视频的流程，一边发一边改出来的。它的一句话定位是：**Agent 驱动的自媒体发布工作台——你对 AI 说一句「整理发布」，一期视频填好七个平台，数据每天自己回来。**

## 三层架构，各管一段

我本来以为这类工具就是一个大脚本模拟点击，打开源码后发现它把职责拆成了清晰的三层，这也是它能持续维护而不变成屎山的关键。

![麦田的三层 Agent 架构](/images/maitian/02-three-layer-architecture.png)

**第一层是发布 Skill**，装进 Claude Code 或 Codex 这类 AI 助手。它负责看片、纠错、为每个平台写差异化文案，然后生成一份标准化的 `publish.json` 发布工程并做校验。我读了 `skills/maitian-publish/SKILL.md`，里面把 B站、小红书、抖音、视频号、YouTube、X、Instagram、Threads 每个平台的文案章节、字段名都规定得很死，因为后续的 `make-publish` 脚本就靠这些字段名取文案。

**第二层是麦田发布助手，一个 Chrome 扩展**，在 Chrome 应用商店上架、自动更新。它负责真正打开各平台上传页、传视频和封面、填文案、设定时。把易变的平台适配逻辑放在可热更新的扩展里，是个很聪明的工程决策——平台改版时，扩展更新一次，所有用户自动生效，不用动主程序。

**第三层是麦田 Hub，一个 Node 守护进程**，也是本仓库的主体。它管分发计划、调度、防重、等你点发布、到点取链接、每天采数据，再加上一个网页大屏和飞书卡片通知。它用的是 Node.js 22.5 内置的 `node:sqlite`，数据存在本地 `data/hub.db`，不需要你额外装任何数据库。

我数了一下代码量：`src/` 目录 35 个文件、3529 行，全仓库 JS/MJS 共 70 个文件、6064 行。对一个功能这么多的系统来说，这个体量相当克制。

## 最反直觉的设计：它故意不帮你点发布

这是整篇文章我最想讲的一点。

市面上的「自动群发」「群控」工具，卖点往往是「全自动、无人值守、一键全发」。麦田反其道而行：**国内的 B站、抖音、小红书、视频号四家，它只负责把表单填好，然后停下来，最后那一下「发布」必须你自己点。** 守护进程还会每 20 分钟提醒你一次。

![自动提交与人工点发布的边界](/images/maitian/03-auto-vs-manual-boundary.png)

我在 `config.example.json` 里核对了这个划分：`manual`（人工点发布）数组是 `bilibili、douyin、xhs、channels` 四家国内平台；`auto`（回读核对后自动提交）数组是 `zsz（知识站）、x、youtube、instagram、threads` 五家。

为什么要这样？因为作者清楚平台风控的逻辑。全自动批量发布恰恰是最容易触发风控、导致封号的行为。把「填写」这种重复劳动自动化，把「发布」这个不可逆、高风险的动作留给人，是一条能长期用下去的安全边界。README 里「各平台的坑」一节几乎全是这种实战经验，比如：

- 小红书只走最保守的路：只读页面已渲染的内容、像人一样滚动点击，不在页面里直接调接口，保持低频；
- 同一条视频每个平台只传一次，反复重传最容易触发风控，中控专门做了防重；
- 视频号的定时可能被平台自己改掉（作者实际遇到过 +2 小时），`sync` 会拿平台记录和计划比对，不一致就发飞书告警卡片。

这些不是文档里的正确废话，而是真踩过坑才写得出来的细节。

## 不只是发布，而是数据复盘闭环

如果只能发，它和普通工具有限。麦田的另一半价值在数据。它用农业的隐喻把整个流程分成三段。

![播种、长势、收成的数据闭环](/images/maitian/04-data-loop.png)

**播种就是发布**：按批次填好七平台、排进分发计划。批次也是有讲究的，配置里建议国内平台两两一批，因为一次传太多会互相抢带宽导致超时。

**长势是流量和粉丝**：每天上午自动采一次各期在各平台的播放、互动和粉丝数；新发布的内容头三天每 6 小时采一次，抓住冷启动窗口。采集失败时保留上一次成功数据，不会让大屏变空白。

**收成是转化**：接上你自己的站点后，通过 UTM 参数追踪是哪一期、哪个平台带来了注册、会员、订单和收入，形成「播放 → 注册 → 会员 → 收入」的漏斗。

更打动我的是它的复盘机制：每期内容发布后第 1、3、7 天自动出复盘卡片，做同龄对比（第 N 天对第 N 天，而不是拿老内容的成熟期欺负新内容），每周一自动出周报。这套节奏和一个专业运营的手动复盘习惯完全一致，只是它自动帮你做了。

## 安全边界，是个人开发者最该学的部分

我特意把安全设计单独拎出来，因为这类能登录你所有账号的工具，信任是第一位的。

![麦田的安全与风控设计](/images/maitian/05-safety-risk-control.png)

最关键的一条：**它不存任何平台密码**。它操作的是一个专用 Chrome 浏览器，用你自己登录好的登录态（通过 CDP 9333 端口通信）。我核对了 `.gitignore`，`config.json`、`data/`、`chrome-profile/`、`logs/` 这些含敏感信息的路径全部不进 git。

其次是前面讲过的不调接口、不重复传、人点发布。另外它只读你自己账号的创作者后台，**不做任何互动自动化、不碰别人的账号**——这意味着它不会去刷量、不会去批量点赞评论，从根上避开了灰产地带。不用的平台还可以停用，停用后不体检、不发布、不采粉丝。

它甚至考虑到了视频文件本身的坑：成片必须是 faststart 编码（moov 元数据在文件头），否则小红书会报「无视频流信息」、抖音出不了表单，这一步在 `validate` 阶段就会被拦下。

## 三级上手，不必一次配齐

很多强大工具的死穴是上手门槛太高，麦田用三级路径解决这个问题。

![L1/L2/L3 三档上手路径](/images/maitian/06-three-levels.png)

**L1 只看数据，大约 30 分钟**：装上麦田、在专用 Chrome 登录各平台，就能拿到全平台粉丝、已发作品的播放互动、网页大屏和飞书日报。已经发过的内容用 `hub adopt` 登记即可，不用重新发布。

**L2 分发，再加 1 小时**：装上 Chrome 发布助手和发布 Skill，就能一期填好七个平台、定时发布、自动取链接。

**L3 转化，看你的站点开发量**：按 `src/site.mjs` 的接口接上自有站点，才能看到注册和收入归因。

安装方式也给了三种：macOS 一行 curl 脚本、Windows 的 PowerShell 脚本（社区贡献）、以及最有意思的「Agent 自动安装」——你把一段话复制给 Claude Code，它会自己读安装指引、装好本体并把 Skill 装进它自己的技能目录。环境要求是 macOS 或 Windows 10/11、Node.js ≥ 22.5、Google Chrome。

## 我实跑了它的测试：149 个全过

光看 README 不够，我把测试套件真跑了一遍。这个仓库有 26 个测试文件，覆盖了 B站/抖音/小红书账号采集、飞书通知、小鹅通销售、站点转化、配置管理等模块。用 `node --test tests/*.test.mjs` 跑下来：**149 个测试全部通过，耗时 9.2 秒，零失败。**

对一个只有 13 天历史的个人项目来说，这个测试密度和通过率是相当难得的——它说明作者是在用工程化的方式维护，而不是堆 demo。这也解释了为什么 7 个贡献者敢在这么短时间内一起协作。

## 谁适合，谁先等等

**适合的人**：同时运营 3 个以上平台、被重复发布折磨的个人博主和小团队；想要统一数据大屏、又不放心把密码交给云端 SaaS 的人；已经在用 Claude Code / Codex、希望把发布也纳入 Agent 工作流的人；以及想学习「Chrome 扩展 + Node 守护进程 + 本地 SQLite」这套桌面自动化架构的开发者。

**先等等的人**：只有单平台、发得也不频繁的人，这套系统对你过重；没有一台常开的 Mac 或 Windows 电脑的人（它需要常驻运行）；追求完全无人值守、连发布都不想点的人——它在国内平台上刻意不满足这个需求，而这恰恰是它的安全底线。

最后照例做个边界提示：麦田是 MIT 许可，代码开放可自托管，但它通过浏览器操作真实平台账号，任何自动化都存在平台规则变化的风险，重要账号建议先用小号验证节奏。它能降低的是重复劳动，而不是让你无视平台规则。

项目地址：[https://github.com/CzzzzzzJ/mdldm-maitian](https://github.com/CzzzzzzJ/mdldm-maitian)

在我看来，麦田最有价值的不是它能自动发多少平台，而是它清醒地知道**哪些事情不该自动化**。在一个人人都在鼓吹「全自动」的时代，这种克制反而成了最稀缺的产品判断力。
