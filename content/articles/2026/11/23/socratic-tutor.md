最近 GitHub 上有个数据挺反直觉：量化交易巨头 Jane Street 在 11 月初开源了一个叫 [agent_skills](https://github.com/janestreet/agent_skills) 的仓库，没有一行可执行代码，核心就是一个 5KB 左右的 Markdown 文件，结果上线约 20 天 Star 就破了万。我克隆下来逐行读完，发现它火得并不偶然——它卖的根本不是功能，而是一套把"LLM 直接给答案"整个反过来的教学协议。

先说清楚这东西到底是什么。它目前只包含一个技能 `socratic-tutor`，作用是把任意一个支持 `SKILL.md` 格式的 AI agent，变成一个用苏格拉底式提问（Socratic method）来教学的严格私人导师：不讲课、不直接给答案，主要靠一个接一个的问题，逼你自己推理、预测、解释，直到真正掌握。

我没有停留在"收藏等于学会"，而是把仓库完整克隆到本地核验了一遍，这篇文章讲四件事：它解决的真问题、它的完整机制、一个多数人没看出来的工程思想，以及你到底该不该用、怎么用。

## 一、先看家底：4 个文件、零行代码，凭什么破万星

先上我本地核验的一手事实，而不是照抄 README 的宣传语。

整个仓库去掉 `.git` 之后只有 4 个文件：`README.md`（1603 字节，说明怎么装）、`socratic-tutor/SKILL.md`（5243 字符，全部价值所在）、`LICENSE.md`（MIT）、`CONTRIBUTING.md`（贡献规则）。我特意扫了一遍文件类型，**没有任何 `.py`、`.js`、`.ts`、`.go`、`.rs` 之类的可执行源码，零依赖、零构建、零安装脚本**。换句话说，它不是一个软件，而是一份可以被任何 agent 读取的"行为规范"。

GitHub 元数据也印证了它的传播速度：仓库 2026-11-03 创建，到我写这篇文章时约 20 天，Star 数 10681、Fork 739，open issues 为 0，默认分支 master，License 是 MIT。出品方 Jane Street 是全球最知名的量化交易公司之一，也是 OCaml 语言的主要推动者，对"严谨流程"这件事有近乎偏执的追求——理解这个背景，后面你就能看懂它的提示词为什么写得这么"不近人情"。

## 二、它解决的真问题：你以为的"学会"，可能只是"看懂"

用大模型学习有个普遍的通病：你问什么，它几秒钟就给你一个结构完整、措辞漂亮的答案。你读完点头说"懂了"，但这种"懂"非常脆弱——因为整个推理过程是模型替你完成的，你只是被动接收了结论。一周后让你不看答案自己推一遍，大概率卡住。更糟的是，现在的模型被对齐得非常"友善"，你回答得半对半错，它也倾向于先夸一句"Great try"，再温柔地把正确答案补上，于是你对自己的真实水平产生了系统性的高估。

普通的自定义指令（system prompt）为什么救不了？因为它们大多只规定了"语气"和"角色"——比如"你是一个资深老师，请耐心讲解"。这类指令没有可执行的教学状态机：它不做入学诊断，不知道你现在处于什么水平；不追踪每个子技能的掌握度，讲深讲浅全凭感觉；不做间隔复习，学完就结束；更没有严格的通关标准，你说懂了它就当你懂了。

`socratic-tutor` 的核心价值，就是把上面这些缺失的环节，用一份纯文本协议补齐了。

## 三、完整机制拆解：一套有诊断、有状态、有终考的教学闭环

我把 SKILL.md 的逻辑拆成六个环节，它不是一句"多提问少给答案"的口号，而是一套环环相扣的流程。

**第一关是意图守卫（Guard）。** 技能明确区分"一次性问答"和"持续教学"。如果你只是问"explain X""what is X"，它会正常回答、不会自作主张启动测验；只有当你明确说"teach me / tutor me / quiz me / drill me / help me master"这类触发短语时才开课。意图模糊时它会先问一句"你是想要个快速答案，还是要我正经把你教会？"——原文写得很直白：错误启动会浪费用户一次不想做的测验，而确认只需要一个词。

**第二步是入学诊断。** 开课之后它先不教任何东西，而是把主题拆成 4 到 10 个具体子技能，然后问 3 到 5 道由易到难的探测题，一次只问一道，定位你在每个子技能上的真实起点，再给你看初始技能地图、建议从哪里开始（你可以否决它的建议）。

![把"学会了"变成可追踪的 0-5 级技能地图](/images/socratic-tutor/02-skill-map.png)

**第三步是技能地图，这是它的"状态机"核心。** 每个子技能都按 0 到 5 级追踪：0 没听过、1 听说过、2 能跟上、3 能在帮助下做、4 能独立做、5 能教别人并处理边界情况。每次等级变化，它都会用块字符（`U+2588` 实心块和 `U+2591` 浅色块）重画一张 ASCII 进度条地图，带 overall 百分比和"当前重点"标记，就像终端里的进度面板。

**第四步是追问循环，也是苏格拉底法的灵魂。** 它一次只问一个问题，问完立刻结束消息、闭嘴等你回答，不在同一轮里塞提示或标准答案。问题的设计偏高级：让你预测结果、解释原因、找出一个看似有理实则错误的论断里的漏洞、把概念迁移到新案例、或者把两个知识点连起来。关键规则是——**你答错时，它不给答案，而是问一个更窄的问题，逼你自己发现推理里的矛盾；只有连续 2 到 3 次失败，它才会简短讲解，而且讲完立刻换个角度重新测同一个点。** 你答对了也别高兴太早，它偶尔会扮演魔鬼代言人（"你确定吗？那如果出现 X 情况呢？"），逼你在压力下为正确答案辩护。

![普通 AI 答题机 vs 苏格拉底私教](/images/socratic-tutor/03-ai-vs-tutor.png)

**第五步是间隔复习和严格评分。** 它会不打招呼地重测你早先学过的子技能，如果复习没过，直接降级、重新练。评分规则写得相当硬核：级别是"挣来的不是给的"，升级需要在 2 次以上独立验证中表现出来，而且至少有一次是无提示回忆（不是刚告诉你答案就让你复述）；模糊或部分正确的回答一律不算对；想升到 5 级，你必须能处理一个边界/对抗问题，并且把概念讲清楚到"它愿意相信你能去教别人"的程度。它还明确要求"不要讨好"，原文直接说一句"Not quite——why would X happen if Y were true?"胜过"Great try!"。

**最后是终考。** 只有当每个子技能都达到目标等级（默认 4/5，要求完全掌握则是 5/5）课程才结束，然后跑一次覆盖全部内容的混合终考，每个子技能至少一题、外加一道综合题。通过才展示最终地图和你的薄弱点总结，不过就打回循环继续练。

## 四、非显然的工程洞察：提示词的高级形态是"协议"，不是"咒语"

读完源码我最大的收获，是看清楚了一个很多人对提示词工程的误解。

市面上大量提示词在比拼"写得多华丽、人设多丰满"，而 Jane Street 这份东西几乎没有形容词，全是规则、状态和验收标准。它的内核其实和量化交易同源——**可量化、可审计、反人性**：把模糊的"我学会了"变成 0 到 5 级的可追踪状态，要求"无提示回忆"这种客观证据才算数，甚至刻意压制模型讨好用户的本能。这是一种典型的工程思路：不相信主观感觉，只相信可重复验证的信号。

这也解释了它为什么能用纯 Markdown、零代码实现，还能被任意 agent 复用。因为机制不依赖任何特定框架或 API，全部写死在那份 SKILL.md 的协议里：触发条件是什么、状态怎么存（ASCII 地图）、每一步的输入输出规则、什么情况下升级或降级、何时结束。它甚至考虑到了会话连续性——提供 `save state` 命令导出一个紧凑状态块（主题、技能地图等级、误解记录、已覆盖内容），你把它粘进一个新会话再用 `resume from:` 就能接着学，等于用纯文本实现了"存档/读档"。

所以更准确的说法是：**高级提示词工程不是写咒语，而是设计一个有状态、有守卫、有严格验收标准的轻量协议。** 这一点对想做 AI 教育产品、或者想给自己的 agent 加教学/考核模块的开发者，参考价值比技能本身更大——你完全可以照着它的状态机结构，改造成自己领域的训练流程。

## 五、5 个随时可用的命令，和最小上手路径

学习过程中你随时可以输入这几个命令来控制节奏：`show progress` 重画技能地图；`harder` / `easier` 当场调难度；`just tell me` 只对当前这一题跳过苏格拉底模式、直接讲解；`save state` 导出存档块；`resume from:` 粘贴存档块续学。

![适合谁、谁先缓一缓，以及 5 个随时可用的命令](/images/socratic-tutor/04-who-and-commands.png)

安装也确实是 5 分钟的事，分两种情况。如果你用的是支持通用 `SKILL.md` 格式的编程 agent（比如 Claude Code、Codex 这类带 skills 目录的工具），直接把 `socratic-tutor` 整个目录复制进 agent 的 skills 文件夹，然后对它说"teach me 某某主题"即可。如果你用的是普通聊天机器人、没有 skills 机制，就把 SKILL.md 的正文整段粘进对话框或系统提示词，再跟上你想学的内容，效果一样。

## 六、谁该用、谁先缓一缓：一份不吹不黑的判断

**适合的人：** 想真正吃透一门硬知识（数学、外语、编程、金融概念等）而不是只求"看懂"的自学者；备考、需要长期留存而非临时记忆的人；愿意被追问、能接受答错被当场拆穿的人；以及想给产品加教学/考核模块、需要一套可借鉴状态机的开发者。

**先缓一缓的人：** 只想快速查个答案、要现成代码片段的人——它故意慢、故意不直接投喂，追求效率时会让你着急；需要多模态或真实动手实验环境的场景——它本质是纯文本协议，工具调用只是可选项；以及只能用碎片时间、无法连续多轮对话的人，这套状态机需要连贯的学习节奏才能推进。

还有一点要如实说明：Jane Street 在贡献指南里讲得很清楚，这个仓库是从他们内部日常使用的仓库导出的，他们只分享"自己验证过有用"的东西，**不接受新增技能、也不接受修改现有技能文案的 PR**（报告 bug 的 issue 欢迎）。所以它不是一个社区大杂烩，而是一份观点鲜明、带强烈个人（公司）方法论色彩的教学法，你可以借鉴、可以自己改一份用，但别指望它变成大而全的技能市场。目前 open issues 为 0、仍在很早期，后续会不会加更多技能值得观察。

## 结语

一个 5KB 的文本文件、零行代码、20 天破万星，这个反差本身就是最好的注脚：在大家都在卷模型参数和功能数量的时候，真正稀缺的是"怎么用 AI 才能真的学到东西"的方法论。Jane Street 给出的答案很古典——回到两千多年前苏格拉底的助产术，再用现代工程的状态机和严格验收把它固化下来。

它不会让你学得更快，甚至会让你学得更慢、更费劲；但它瞄准的是"真的掌握"，而不是"感觉自己懂了"。如果你已经厌倦了被 AI 一口一口喂答案，想找个不会讨好你的老师，值得花 5 分钟把它装进你的 agent 试一次。
