最近身边好几个朋友都退订了 Claude Code，转回去用 OpenAI Codex。

我自己两个都用了大半年，聊聊真实感受。

## 核心问题其实不是体验，是钱

Claude Code 每个月 20 美元，一年就是 1700 块人民币。

但大多数开发者不是每天都需要 AI 帮你写代码。

我平均下来一周也就用两三次，每次几十上百 tokens。一年用 Codex 按次付费，总共才花了不到 30 美元。

差了整整 8 倍。

这不是我一个人的情况。

有个朋友公司报销 Claude Code 订阅，他自己做业余项目还是偷偷用 Codex——不想占公司额度，自己掏腰包真的心疼。

## 还有一个隐性原因：Claude 有时候太"聪明"了

你让它改个小功能，它直接给你重写半个文件，引入一堆你根本不需要的抽象和设计模式。

改完你还要花时间把它改回来，得不偿失。

Codex 就简单多了——你写到哪，它补到哪，不多管闲事，不打乱你的思路。

## 选 AI 编码工具，问自己这四个问题

![选择工具自检框架](/images/claude-code-被退订用户转用-codex订阅制为什么赢不了按次付费/claude-codex-checklist.png)

### 1. 你是每天都用，还是偶尔才用？
- 每天写代码都依赖 AI → 选订阅制划算
- 遇到难题才找 AI → 按次付费更便宜

### 2. 你要 AI 帮你"做完"，还是"做一半"？
- 从头写框架/整体重构 → Claude 更擅长
- 补完你写了一半的逻辑 → Codex 不添乱

### 3. 费用公司报销，还是自己掏腰包？
- 公司报销 → 随便选体验好的
- 自己掏钱 → 先算清楚你实际用了多少

### 4. 需要读整个项目，还是只补当前文件？
- 读整个代码库找 bug → Claude 大窗口优势明显
- 日常写功能补代码 → Codex 响应更快，也够用

## 最后说一句

我不觉得 Claude Code 不好，它确实是目前体验最好的 AI 编码助手之一。

但问题是，大多数开发者并不需要"体验最好的"。

他们需要的，是"够用又够便宜的"。

当新鲜感过去，大家还是会用脚投票，回到最适合自己使用习惯的工具上去。
